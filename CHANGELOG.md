# Changelog

All notable changes to `@ashlr/lexicon` are recorded here. The format follows Keep a Changelog. Versions follow semver.

## 0.3.2 (2026-09-20)

### Added
- README demo GIF recorded on the live site (`docs/assets/demo.gif`).

### Added
- One-click pairing between the browser extension and the local API. `lexicon serve --pair` checks `/health`, then opens `http://127.0.0.1:41733/pair` in the default browser (`open` / `xdg-open` / `start`, no shell); the new `GET /pair` page carries the bearer token in `<meta name="lexicon-token">` (plus `lexicon-port` and `lexicon-version`) and the extension's new `pair.js` content script, registered for that URL only, reads it, proves it against `GET /stats` through the background worker, stores base URL, token and mode `api`, and writes "Paired with lexicon serve (N terms)" into the page. No extension after 3 seconds: the page shows install instructions. Pasting the token from `lexicon serve --show` into Options remains the manual fallback.
- Extension Options shows the pairing state ("Paired with http://127.0.0.1:41733 (token stored)" or "Not paired") with a "pair in this browser" / "pair again" link to `/pair`, and reflects a pairing done in another tab without a reload. `extension/manifest.json` adds `http://localhost:41733/*` to `host_permissions`; `scripts/build-extension.mjs` bundles `pair.ts` as a classic script like `content.ts`.
- `src/serve/server.ts` exports `PAIR_PATH`, `PAIR_META`, `PAIR_HEADERS`, `PAIR_INSTALL_HINT_MS`, `pairPageHtml()`, `isPairHost()`, `isLoopbackAddress()`; `src/cli/cmd-serve.ts` exports `runServePair()`, `pairUrl()`, `browserOpenCommand()`; `extension/src/shared.ts` gains the `pair` request, `PairReply`, `pairUrl()`, `pairableBaseUrl()`, `TOKEN_RE`, `PAIR_HOSTS`.

### Security
- `GET /pair` needs no bearer but is served only to a loopback peer whose `Host` header is exactly `127.0.0.1:<port>` or `localhost:<port>` (403 otherwise, which defeats DNS rebinding), with `Cache-Control: no-store`, `X-Frame-Options: DENY`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'` and `Referrer-Policy: no-referrer`; the page runs no script and makes no external request. The background worker refuses to pair with any base URL that is not plain `http://127.0.0.1:<port>` or `http://localhost:<port>` and stores nothing until `/stats` accepts the token. See SECURITY.md.

## 0.3.1 (2026-09-19)

First release on the npm registry: `npm i -g @ashlr/lexicon`.

### Fixed
- Matcher: a window made of stoplist words plus one- or two-letter abbreviations ("ms window") is never matched phonetically or fuzzily; implicit split aliases such as "open ai" still match exactly.
- `lexicon voice --toggle` start is atomic: the state file is claimed with an exclusive create before ffmpeg spawns, so two racing hotkey presses start one recorder (the second prints `recording` and exits 0); a start that dies before spawning leaves a provisional record that is replaced after 5 seconds.
- `setup_lexicon` from the plugin bundle wrote a login service that could not run: `lexicon serve --install` resolved the CLI relative to its own module, which inside `plugin/mcp-server.mjs` is `plugin/index.js`, then booted out the working LaunchAgent under the same label and left the new one crash-looping (dogfood 2, bug 2). CLI resolution now lives in one place, `resolveCliEntry()` (`src/cli/cli-entry.ts`): an explicit `cliPath`, `$LEXICON_CLI`, the package's `dist/cli/index.js` found by walking up to the `@ashlr/lexicon` package.json (works from `dist/` and from `plugin/`), else a `lexicon` on PATH resolved through its symlink; `setup` passes `<cliDir>/index.js`, and `resolveIntegrationPaths()` (the client installers) shares the same package lookup. `--install` refuses to write a plist or unit whose program path does not exist and never runs `launchctl bootout` before the new file is known to be valid.
- The UserPromptSubmit hook normalized pasted dictionary data: a Wispr row `versel,Vercel` became `Vercel,Vercel` and Vercel got a hit (dogfood 2, finding 7). Lines that read as a dictionary export (a `word,` / `canonical,` / `original,` / `shortcut,` header with the rows after it, even behind a prose prefix, or three or more consecutive `a,b` rows with the same column count and no whitespace around the commas) get no corrections and no hits; prose with commas and the sentences around a block are still corrected (`dataBlockSpans`, `dropDataBlockSpans`).
- `lexicon setup` no longer seeds a person or company that the global lexicon already has (case-insensitive) and the harvest skips names the global lexicon covers, so `--person` equal to `git config user.name` and the git author picked up by the harvest no longer produce the duplicate `lexicon doctor` flagged.
- Extension: the precheck cache treated a dry run's `changed: false` as "nothing to fix", so after 250 ms of idle in the composer Enter went through uncorrected on every site. It now looks at the dry run's replacements (`extension/src/content-core.ts`).
- Extension: Grok's composer is a Tiptap (ProseMirror) contenteditable inside the form, not a textarea; the adapter now targets it (`form div.tiptap[contenteditable="true"]`) and keeps the textarea selectors as fallbacks (`extension/src/adapters.ts`).
- Extension: a message with two or more corrections was garbled on Perplexity (Lexical commits an edit in a microtask and resolves the next `insertText` against its own pending selection). `applyCorrections` is now async and lets the editor settle between ranged edits; the first edit and text fields stay synchronous (`extension/src/editable.ts`).

### Added
- `lexicon doctor` / `lexicon_doctor` check the login service: on macOS `launchctl print gui/$UID/ai.ashlr.lexicon.serve` plus the plist's program path (`✓ ... loaded (<path> exists)`, `✗ ... points at a missing file: <path> (run: lexicon serve --uninstall && lexicon serve --install)`, `! ... installed ... but not loaded`, `·` when none is installed); on Linux `systemctl --user is-active lexicon-serve.service` and the unit's `ExecStart`. `DoctorDeps` gains `home` and `uid`; `checkLoginService()` is exported.
- `lexicon setup --harvest` (with `--yes` the repo harvest now runs only when this is passed; `--no-harvest` still skips it without a prompt; a terminal still shows the candidates and asks). `setup_lexicon` gains `harvest?: boolean` (default: not harvested on apply; the plan lists `wouldHarvest` either way so the model can offer them).
- `LEXICON_SERVE_LABEL` overrides the launchd label used by `lexicon serve --install` / `--uninstall` and the doctor (scratch installs beside a real one). `LEXICON_CLI` overrides the CLI path the service runs.

### Changed
- `lexicon setup`: `--dry-run` prints the plan and writes nothing; under `--yes` the local API login service is installed only with an explicit `--serve` (`--no-serve` still skips it without a prompt). `setup_lexicon` previews by default and returns a `SetupPlan`; `apply: true` installs only into the `clients` given (omitted = none) and the login service only with `serve: true`.
- `SetupSummary.clients[].detail` is the config file the installer wrote (`~/.cursor/mcp.json`, `~/.claude/settings.json (unchanged)`), reported through the new `onWritten` callback in `InstallDeps` / `InstallClaudeDeps`, instead of the installer's last output line (the export hint).
- Wording (dogfood 2, findings 5, 6 and 8): the SessionStart onboarding note names the three questions (company/product spelling and pronunciation, the user's own name, which of Claude Code, Claude Desktop, Codex, Cursor, Windsurf, Gemini CLI, VS Code) and says to offer, not run; the skipped-project hook note and the `trust_project` description say to review through `trust_project` `status` (or `lexicon trust`) and not to open the file with Read or cat; the `setup_lexicon` description states what it asks for and what it does not do (no unlisted clients, no harvest without `harvest: true`, no login service without `serve: true`); `suggest_terms` promotion reasons read `the matcher would guess this as Vercel (3 times in history); make it an exact alias`.
- docs/EXTENSION.md "Supported sites": each row marked verified or assumed with the 2026-09-19 date and the selector that matched live (Gemini's send button is `button[aria-label="Send message"]`; ChatGPT logged out is `textarea#mobile-composer-prompt`).

### Security
- `lexicon voice` creates `<config dir>/voice/` with mode 0700 and its state, history, recorder log and WAV files with mode 0600; the toggle state file is claimed atomically so two hotkey presses cannot start two recorders.

## 0.3.0 (2026-09-19)

One-line install, a setup wizard, agent-native MCP tools and suggestions.

### Added
- `lexicon setup`: the guided first run. Six steps, each one line of output: seed the global lexicon with your name (`git config user.name`) and company (suggested from the package scope or git remote), harvest the repo into the project lexicon, detect and install into agent clients, install the local API as a login service, export for Wispr Flow, Superwhisper or macOS Text Replacement, then a summary card. Every step is idempotent.
- `lexicon setup` flags: `-y/--yes`, `--clients <list|none>`, `--company`, `--person`, `--phonetic`, `--app`, `--export-dir`, `--no-harvest`, `--no-serve`, `--reseed`, `--home`, `--json` (a machine-readable `SetupSummary`). `runSetup()` is exported for the MCP tool.
- Install script: `curl -fsSL https://ashlrai.github.io/lexicon/install.sh | sh` (`scripts/install.sh`, copied into the demo site). POSIX sh; checks Node 20+, installs from npm when published, otherwise from GitHub at the latest tag (`LEXICON_REF` overrides), then runs `lexicon setup` on a terminal (`LEXICON_NO_SETUP=1` skips it).
- Homebrew: `brew install ashlrai/tap/lexicon` (`packaging/homebrew/lexicon.rb`, published to `ashlrai/homebrew-tap`). Depends on `node`; recommends `ffmpeg` and `whisper.cpp` for `lexicon voice`.
- Release assets on every `v*` tag: `ashlr-lexicon-<version>.tgz`, `lexicon-extension.zip`, `lexicon-extension-firefox.zip`, `LexiconBar.app.zip` (built in a second macOS job) and `SHA256SUMS`. `npm publish` still runs only when `NPM_TOKEN` is set. See `docs/RELEASING.md`.
- Seven agent-native MCP tools so an agent can onboard, install, trust, import, diagnose and improve the lexicon without a terminal: `lexicon_doctor`, `install_client` (preview by default), `trust_project` (status with a sanitized preview, trust, untrust), `import_dictionary`, `suggest_terms`, `apply_suggestion`, `setup_lexicon` and `serve_status`. Seventeen tools in total. See `docs/AGENT-NATIVE.md`.
- `onboard` MCP prompt scripting the first-run conversation, and `SERVER_INSTRUCTIONS` that mention onboarding, doctor, suggestions, preview-before-apply and trust-after-preview.
- The SessionStart hook emits an onboarding note when the merged lexicon is empty, at most once per 24 hours (`<config dir>/onboard-note.json`). Never emitted when terms exist.
- `lexicon suggest`: what the lexicon should learn next, mined from `voice/history.jsonl`, hit counters and the repo (`suggestTerms()` in `src/core/suggestTerms.ts`). Four kinds: `alias`, `term`, `never`, `stale`. Ranked by `confidence * log(1 + count)`; evidence sanitized and capped. See `docs/SUGGEST.md`.
- `lexicon suggest` flags: `--json`, `--apply` (walk them, y/n/a/q; a stale removal is never the default), `--yes` (apply everything at or above 0.80; harvest candidates and stale removals never qualify), `--harvest [dir]`, `--limit`, `--project`.
- `runDoctorReport()` and `renderDoctorReport()` in `src/cli/commands.ts`; `lexicon doctor` output is unchanged.
- `docs/QUICKSTART.md`: the five-minute path from the one-liner to a corrected sentence in Claude Code.
- `package.json` `prepare` script builds `dist/` and the plugin bundles on `npm install`, so `npm i -g github:ashlrai/lexicon#v0.3.0` works.
- README: "Try it in 60 seconds", a compact Install section with release downloads, and an "Agent-native" note. Demo site: an Install section with copyable commands and download buttons.
- SKILL.md gains a "Setup and maintenance" section; `/lexicon` gains `setup`, `doctor`, `suggest` and `trust [path]`.

### Changed
- Roadmap: dropped the finished items (browser extension, macOS app, real-audio benchmark) and the stale "No Chrome extension" non-goal.

### Internal
- The agent-native tools import their CLI handlers statically. A module that is also in the static graph must never be dynamic-imported, or esbuild lazy-wraps the shared subgraph and the plugin bundle fails at load.

## 0.2.0 (2026-09-19)

Desktop coverage: surfaces without hooks or MCP.

### Added
- `lexicon serve`: a local HTTP API on `http://127.0.0.1:41733` (`node:http`, no framework). Endpoints `GET /health`, `POST /normalize`, `POST /learn`, `POST /add`, `GET /lexicon`, `GET /export/:format`, `GET /stats`. Bearer token in `<config dir>/serve.json` (mode 0600); CORS only for browser-extension origins or `serve.json.allowedOrigins`; 1 MB body cap; 64 concurrent requests; trust gate unchanged. See `docs/LOCAL-API.md`.
- `lexicon serve` flags: `--port`, `--host`, `--json`, `--quiet`, `--show` (URL and token), `--status`, `--install` / `--uninstall` (launchd LaunchAgent on macOS, systemd user unit on Linux, Scheduled Task instructions on Windows). `createServer()` from `src/serve/server.ts` is embeddable.
- Browser extension (`extension/`, `npm run build:extension`): Manifest V3, fixes names in the ChatGPT, Claude, Grok, Gemini, Perplexity, Poe and Copilot composers when you press send, via the local API or an embedded copy of the lexicon. Chrome, Edge, Brave and Firefox builds. See `docs/EXTENSION.md`.
- `lexicon voice`: local push-to-talk. ffmpeg (16 kHz mono WAV) -> whisper.cpp with the lexicon canonicals as `--prompt` -> `normalize()`. `--copy`, `--paste` (macOS; elsewhere falls back to copy), `--json`. See `docs/VOICE.md`.
- `lexicon voice --toggle`: hotkey mode. First call starts a detached recording (`voice/recording.json`), second call stops, transcribes and outputs; `--status` reports `recording since <time>` or `idle`.
- `lexicon voice` options: `--model <name|path>` (default `base.en`, auto-downloaded from Hugging Face into `<config dir>/models`; `LEXICON_WHISPER_MODELS` overrides), `--device`, `--list-devices`, `--seconds`, `--lang`, `--translate`, `--no-prompt`, `--no-history`, `--quiet`. Exit 2 with install hints when ffmpeg or whisper-cli is missing (`LEXICON_WHISPER_BIN`, `LEXICON_FFMPEG_BIN`), exit 3 when nothing was heard.
- Every voice transcription appends to `voice/history.jsonl` (newest 1000 lines) and records hits. `lexicon doctor` reports whisper-cli, ffmpeg, the default model and the macOS Microphone permission note.
- LexiconBar, a native macOS menu bar app (`apps/macos/LexiconBar`, SwiftPM, no dependencies) that fronts the CLI: push to talk (⌃⌥Space) via `lexicon voice --toggle --json`, "Fix clipboard now" (⌃⌥V) via `lexicon daemon --once`, supervision of `lexicon daemon` and `lexicon serve`, a "Last correction" submenu, Start at login, notifications and Preferences. `scripts/build-macos-app.sh` builds and ad-hoc signs it. See `docs/MACOS-APP.md`.

### Changed
- Matcher: an ordinary word is no longer rewritten to an alias-less sound-alike term (`lacks` became `Locus` in production). The built-in stoplist moved to `src/core/stoplist.ts` and grew from about 600 to 3376 words in their usual inflections; it still blocks only the phonetic and fuzzy passes and implicit aliases, so explicit aliases win.
- Matcher: a single-token phonetic candidate must also resemble the alias in spelling, more so the shorter its metaphone key (similarity 0.8 on a 3-consonant key, 0.65 on 4, none on 5 or more). Benchmark unchanged on positives; prose false positives incl. expected-hard 14.2% -> 12.5%. A bare `entire` no longer becomes `Entire.io`; list it as an alias to opt in.
- Matcher: a name glued to an identifier is left alone in every pass, the exact alias pass included (`@ashlr/lexicon` became `@Ashlr.AI/lexicon` in production). A window directly preceded by `@ / # : \ ~ _ -` or followed by `/ \ _` is skipped; possessives, sentence punctuation and spaced hyphens still match. With `skipCode` on, a whitespace-free `scope/name` slug counts as a path. Benchmark unchanged on every headline number.

## 0.1.0 (2026-09-19)

Initial release.

### Added
- `lexicon review` re-reads the file before its final write and merges hits, aliases and terms changed elsewhere while it ran.
- The UserPromptSubmit hook and the clipboard daemon (loop and `--once`) record `hits` best-effort in the background, so `lexicon stats` counts hook-only and clipboard usage.
- Core exports `stripControlChars`, `sanitizeForDisplay`, `DISPLAY_MAX_CHARS`.
- `parseCorrection` stops the heard side at a sentence boundary: "it's Ashlr.AI not Ashlur. remember that." yields `heard: "Ashlur"` and a following sentence ("... not Ashler. Now deploy it to Vercel.") is ignored. A period stays inside a bare word only when something follows it directly (`Ashlr.AI`, `Entire.io`, `README.md`).
- The UserPromptSubmit hook no longer normalizes the words being corrected: on a correction prompt it drops any replacement overlapping `heard` or `meant`, rebuilds the corrected prompt from the rest, records no hit for the dropped terms, and emits only the correction note when nothing else changed. The note names its fields (`heard: "Ashlur", meant: "Ashlr.AI"`), tells the model to pass only the name when the capture carries trailing words, and ends with "Then continue with the rest of the message."
- README: manual installs do not load `SKILL.md`; a "Headless and scripted use" note (`claude -p`, `--allowedTools mcp__lexicon`, `LEXICON_PATH` reaching hook and server); `lexicon stats` counts hook matches from any session. SKILL.md: trailing-word guidance for the hook's `heard`, and the one-time ToolSearch turn in sessions with many MCP servers.

- Lexicon file format (`version: 1`): terms with `canonical`, `aliases`, `phonetic`, `category`, `notes`, `never`, `caseSensitive`, plus tool-managed `source`, `createdAt`, `hits`; settings `minConfidence`, `phonetic`, `fuzzy`, `protectedWords`, `skipCode`.
- Global file at `~/.config/lexicon/lexicon.yaml` (override with `LEXICON_PATH` or `XDG_CONFIG_HOME`) and project `.lexicon.yaml` at the git root. Project wins on collision, aliases unioned.
- Matcher with three tiers: exact alias, phonetic (double metaphone), fuzzy (Damerau-Levenshtein). Built-in stoplist of about 300 common English words, `protectedWords`, per-term `never`, code span and URL skipping, three-character minimum for guessed matches. Explicit aliases always beat the stoplist.
- Matcher precision (benchmark in `docs/BENCHMARK.md`, prose false positives 18.9% -> 0.0% excluding expected-hard, positive sentence accuracy 88.1% -> 94.2%): exact hits win overlap resolution; inexact windows never start or end on a function word; possessives survive phonetic and fuzzy matches; spans already equal to a canonical are claimed; no phonetic match on keys under 3 characters, windows under 4 letters or spelled-out aliases; lone lowercase words against aliased terms need 0.88; diacritics folded in the exact pass; transposition-aware similarity.
- Matcher: a capitalised sound-alike is no longer rewritten to an aliased term on a weak phonetic hit (`Inter`, the font, became `Entire.io` at 0.86 in production). The 0.88 aliased-term bar now applies to every single-token phonetic candidate regardless of case, and a lone candidate that keys alike only because double metaphone folded its initial vowel (`inter` / `entire`, `email` / `yaml`) must share its first letter or reach similarity 0.6. Benchmark unchanged on positives (94.2% / 96.5% recall); prose false positives incl. expected-hard 15.0% -> 14.2%.
- `normalize` with replacement offsets, reasons, confidence and a one-line-per-change diff summary. Dry-run mode.
- Alias suggestion (`suggestAliases`) that generates likely STT misspellings of a canonical.
- Correction learning: `parseCorrection` recognises "it's X not Y", "I said X not Y", "I meant X not Y", "not Y, X", "replace Y with X", "Y -> X", "Y should be X", "spelled X" and quoted forms; `learnCorrection` adds the heard form as an alias of the matching term or creates a `source: learned` term; `suggestCanonicalFor` returns the closest existing terms for "did you mean".
- Usage stats (`computeStats`): term and alias counts, total hits, top ten terms, never-hit terms, per-category, per-source and per-file breakdowns.
- Repo harvester: package and module names, PascalCase identifiers, git authors, directory name, README proper nouns. Bounded scan (5000 files, 512 KB per file), ignores build and dependency directories.
- Exporters (15): `wispr`, `superwhisper`, `whisper-prompt`, `macos`, `claude-md`, `csv`, `json`, `deepgram`, `espanso`, `assemblyai`, `azure`, `google`, `openai`, `text`, `markdown`.
- Importers (7, plus `auto` content detection): `wispr`, `superwhisper`, `macos`, `espanso`, `text`, `csv`, `json`. Rows merged by canonical; `text`, `csv`, `macos` and `json` round-trip with their exporters. Inputs over 8 MB are refused.
- MCP stdio server `lexicon-mcp` with tools `normalize_transcript`, `add_term`, `remove_term`, `list_terms`, `harvest_repo`, `export_lexicon`, `learn_correction`, `suggest_canonical`, `lexicon_stats`; resources `lexicon://me` and `lexicon://json`; prompt `voice-context`; server `instructions` sent at connect. `normalize_transcript` bumps each matched term's `hits`. `list_terms` and `lexicon://me` report a skipped untrusted project file by path only.
- Claude Code hook (`plugin/hook.mjs`, `lexicon hook`), dispatched on `hook_event_name`. `UserPromptSubmit` injects the diff and corrected prompt as `additionalContext`, prints nothing when unchanged, always exits 0, about 100ms measured; when the prompt is a spelling correction it adds a line asking the model to call `learn_correction` (the hook never writes). `SessionStart` (startup, resume, clear, compact) emits the `claude-md` export of the merged lexicon, capped at about 4000 characters with a "... N more terms; read the lexicon://me resource" line; an empty lexicon emits nothing.
- Self-contained Claude Code plugin: `plugin/mcp-server.mjs` and `plugin/hook.mjs` are committed esbuild bundles (every dependency inlined, Node 20+, unminified) that `.mcp.json` and `hooks/hooks.json` point at, so `claude plugin install lexicon@ashlrai` works from a bare clone with no `npm install` or build. `npm run build:bundle` regenerates them; `npm run check:bundle` (run in CI) fails when they are stale; `prepublishOnly` builds them. `plugin/` ships in the npm package; `dist/` stays untracked. The MCP server reads its version from whichever `package.json` (one or two levels up) is `@ashlr/lexicon`.
- Claude Code plugin packaging: `.claude-plugin/plugin.json`, `.mcp.json`, `hooks/hooks.json`, a `lexicon` skill and a `/lexicon` command (`add`, `learn`, `stats`, `harvest`, `export`, `remove`). Marketplace manifest (`.claude-plugin/marketplace.json`): `claude plugin marketplace add ashlrai/lexicon` then `claude plugin install lexicon@ashlrai`.
- CLI `lexicon` (21 commands, global `--cwd`): `init --project`; `add` (`--phonetic --category --notes --never --project --suggest -i`); `remove --project`; `list` (`--json --category --query`); `normalize` (`--json --diff --dry-run --min-confidence --no-phonetic --no-fuzzy --include-untrusted`, always exits 0 and passes text through on error); `harvest` (`--limit --min-count --add --yes -i --json`); `export` (`--out --category --limit`); `import <file> [format]` (`--format --project --dry-run --source --category --json`); `learn` (`--from --project --json`); `stats --json`; `review` (`--never-hit --project --global --category`); `edit --project`; `trust [path]` (`--list`); `untrust [path]`; `path`; `doctor`; `mcp`; `hook`; `daemon` (`--once --paste --interval --dry-run --quiet --backend --which`); `install-claude` (`--apply --scope`); `install [client]` (`--apply --scope --project --home`).
- Interactive CLI workflows, dependency-free (`src/cli/prompt.ts` over `node:readline`) and refusing to run without a TTY: `harvest --add` on a terminal walks candidates with `y`/`n`/`e` (edit aliases)/`c` (category)/`a` (add all)/`q` (`--yes` opts out, `--interactive` forces it); `add -i` turns the suggested aliases into a checklist and asks for the phonetic hint and category; `review` walks existing terms with `k`/`d`/`e`/`p`/`n`/`q` and writes once at the end; `edit` opens the file in `$VISUAL`/`$EDITOR` and validates it afterwards without ever rewriting it.
- `lexicon doctor`: ok/warn/fail/info tiers, exit 1 on failure. Checks both lexicon files, term conflicts (canonical defined in both scopes, alias shared by several terms, alias that is a common English word), the Claude Code wiring (the `lexicon@<marketplace>` plugin in `~/.claude/plugins/installed_plugins.json` or `enabledPlugins`, else the `UserPromptSubmit` and `SessionStart` hooks in `~/.claude/settings.json`; missing hooks are a warning since the plugin provides them), `claude mcp list`, and the clipboard backend (a warning when none is found).
- `lexicon install-claude` and `lexicon install claude` register `plugin/mcp-server.mjs` and merge both `SessionStart` and `UserPromptSubmit` hooks running `plugin/hook.mjs` (falling back to `dist/` paths when the bundles are absent).
- `lexicon install [client]`: prints or (`--apply`) merges the MCP config for `claude`, `codex` (`~/.codex/config.toml`), `cursor`, `windsurf`, `gemini`, `claude-desktop` and `vscode`; `--project` / `--scope project` for repo-level files, `--home` override. Idempotent, keeps unrelated keys, ends with the `lexicon export claude-md` hint for that client's rules file.
- Clipboard daemon for macOS (`pbpaste`/`pbcopy`), Linux (`wl-clipboard` on Wayland, `xclip` or `xsel` on X11) and Windows (PowerShell `Get-Clipboard`/`Set-Clipboard`, CRLF preserved), with loop guard, `--dry-run`, `--interval` and `--quiet`. `lexicon daemon --once` corrects the clipboard once and exits (for a Raycast/Alfred/Keyboard Maestro/AutoHotkey/GNOME shortcut); `--once --paste` also sends Cmd+V on macOS (needs Accessibility permission); `--backend <name>` forces a backend; `--which` prints the detected one.
- Library entry point `@ashlr/lexicon` (`src/core/index.ts`) exporting the store, matcher, normalize, suggest, harvest, learn, stats, exporters and importers with types.
- Accuracy benchmark (`npm run bench`, `bench/`): 398-case corpus, sweep and filter modes, `bench/bench.test.ts` regression guard, results in `docs/BENCHMARK.md`.
- End-to-end suite (`npm run test:e2e`, `tests/e2e.test.ts`) that spawns the real CLI, hook and MCP server against a throwaway HOME.
- `npm run docs:cli` generates `docs/CLI.md` from every command's `--help`.
- GitHub automation: CI (Node 20/22/24, typecheck, build, bundle freshness, test, CLI, hook and MCP smoke), tag-triggered npm publish with provenance and a GitHub release, Dependabot, issue templates (bug report, misheard term), PR template, funding, Contributor Covenant 2.1 code of conduct.
- Docs: README, architecture, research memo, security policy, module contract, contributing guide, annotated example lexicon, client config and library examples.

### Security
- CLI output is sanitized against terminal escape injection: paths, canonicals, aliases, notes, harvest evidence and quoted error text pass through the new `sanitizeForDisplay`; `renderTable` sanitizes every cell. `normalize` stdout is unchanged.

- Project `.lexicon.yaml` files are skipped until approved with `lexicon trust` (preview, sha256 pinned in `<config dir>/trust.json`; `lexicon trust --list`, `lexicon untrust`). A changed file drops back to untrusted until re-trusted. `LEXICON_TRUST_ALL=1` bypasses the gate for CI. `loadLexicon()` takes `includeUntrusted` and reports `projectTrust` / `skippedProject`; `list`, `normalize` (`--include-untrusted`) and `doctor` warn; the hooks and `lexicon://me` add a one-line note naming the path, never the contents.
- Project-scope writes (`init --project`, `add --project`, `import --project`, `learn --project`, `harvest --add`, `review --project`, and the MCP `add_term`, `learn_correction` and `harvest_repo {add: true}` tools) pin the file they wrote as trusted only when it did not exist yet or was already trusted. An existing untrusted or changed file makes the write fail with `ProjectTrustError` before anything is read, so a hostile repo file can never be laundered into trust. `recordHits` silently skips untrusted project files.
- Schema hardening: canonical/alias at most 80 characters, notes/phonetic 200, 64 aliases per term, 5000 terms, no control characters or line breaks; zero-width, bidi and BOM characters are stripped. Lexicon files over 2 MB and imports over 8 MB are refused. The `claude-md` export escapes `|` and line breaks in table cells. See SECURITY.md.

### Internal

- ESM, NodeNext, no default exports, no `any` in public signatures. Cross-module imports go through `src/core/index.js` only.
- `harvest.ts` exports `HARVEST_STOPLIST` (README-word filter), distinct from `matcher.ts` `STOPLIST` (prose guard), to avoid an `export *` collision.
- `src/mcp/server.ts` keeps an `EXPORT_FORMAT_VALUES` tuple with a compile-time exhaustiveness check against `ExportFormat`.
- `hookConfigFor` and `mergeHookIntoSettings` take an optional list of events; `HOOK_EVENTS` is `['UserPromptSubmit', 'SessionStart']`.
- The hook, CLI and daemon tests inject IO and clipboard functions; MCP and CLI tests mock `src/core/index.js`.
- `src/hooks/user-prompt-submit.ts` exports `dropCorrectionSpans(result, correction)` (pure; returns the same object when nothing overlaps). `parseCorrection` runs before `normalize` in the hook so the filter can apply.
- `docs/DOGFOOD.md` records the live run against Claude Code 2.1.257 that found both hook bugs.
