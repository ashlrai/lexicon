# Changelog

All notable changes to `@ashlr/lexicon` are recorded here. The format follows Keep a Changelog. Versions follow semver.

## 0.5.3 (2026-09-20)

Thirty-four commits, most of them written after a fresh-user walkthrough and three rounds of review. The shape of the release is confidentiality and data loss: both desktop apps were reading the text of every field you focused before deciding whether they were allowed to, and six separate paths could throw away something you had dictated or written. Everything below was reproduced before it was touched, and every regression test here was watched failing against the unfixed code.

### Security

- **Both desktop apps read the text of every focused field before deciding whether they were allowed to.** `FocusWatcher` pulled the focused element's full value and cached it, and the poll refreshed that cache four times a second on Windows and twice a second on macOS. The exclusion list and the secret-field heuristic ran a layer above, in `FixEngine`, where all they could do was decline to build a detector for text the process already held. So a password manager's field, a vault note or a TOTP box in an app that was not on the exclusion list sat in memory for as long as it held focus. Nothing was sent anywhere and nothing was logged, so the exposure was a crash dump or an attached debugger, which is exactly the reach the threat model says we do not give it. `SECURITY.md` and the Windows app both claimed the opposite. The decision has moved in front of the read on both platforms: `LexiconBar.Core/FieldGate.cs` and `LexiconBarKit/FieldGate.swift` split a field into the metadata the accessibility tree exposes about it and the single call that pulls the user's text, and decide on metadata alone, so a refused field is never asked for its value on any of the three read paths. `FieldGateTests` drives a field that counts how many times anything asked for its value and asserts the count stays at zero through seven refusal cases.
- **On macOS the probe that decided whether a field was editable was itself a read.** `isEditableText` settled the non-text-role case by copying `kAXValue` to see whether it came back a string, so the user's text entered the process before any refusal could run, on a path that executed for every focused element. `couldBeEditableText` decides from attribute names instead, and whether the value is really a string is answered by the gated read.
- **Turning "Fix everywhere" off left the watcher reading every field and merely declining to correct it.** That switch is the mitigation `SECURITY.md` offers as the last resort, so it has to mean what it says. Off now stops the watcher on both platforms: no focus resolution, no event read, no poll, and the field it currently holds dropped on the spot. Which app is in front is still tracked, because that is metadata.
- **Excluding an app on macOS never reached the read gate.** `@Published` emits from `willSet`, and the sinks in `startFixEverywhere` discarded the value they were handed and read `settings.exclusions` back off the object, so the list pushed into `FixEngine` and on into `FocusWatcher` was the one from before the change. `setExclusions` then found it equal to the list it already held and returned early, and the field in the app the user had just excluded went on being read, POSTed to `/normalize` and rewritten. `Settings` gains `fixSettings` and `fixSettingsChanges`, a `CombineLatest4` that carries the new values through, and `AppDelegate` has one subscription that reads nothing back.
- **The undo hotkey was the one path where excluding an app mid-focus stopped neither the read nor the write.** `performUndo` and `PerformUndo` went straight to the field's value and consulted the gate afterwards, on both platforms. Both go through the gate first now, and a refusal drops the ledger entry with it.
- **On Windows, measuring the caret ran two calls ahead of the gate.** `Settle` called `CaretEnd` before the refusal check, and measuring the caret means measuring the document in front of it. The refusal runs first now, and `CaretEnd` and `SelectionMatches` take the same `MaxFieldLength` cap as every other read instead of `GetText(-1)`.
- **Un-excluding one app admitted its whole vendor.** `AppExclusions.include` deleted the rule that matched rather than the entry the user clicked, so re-enabling a single 1Password process removed `com.1password.*` on macOS and `1password*` on Windows. It removes only the exact entry now and returns the rule that still covers the app, which the tray names instead of showing a switch that springs back.
- **An emptied exclusion list on Windows said nothing.** It is one textbox that a single Ctrl+A can clear, and clearing it used to lose terminals, `lsass`, `logonui` and every password manager with no indication at all. `AppExclusions.IsEmpty` now drives a warning in place of the usual hint and a confirmation before saving one. An empty list still means "exclude nothing", the same as on macOS.
- **The two Windows security decisions now live where a test can reach them.** `LexiconBar.Core.Tests` references `LexiconBar.Core` and nothing else, because `LexiconBar.App` targets `net8.0-windows` and cannot load on the Linux runner that gates this repo, so a decision inside the App project had no test that would go red if it were reordered back. `ReadPolicy` holds the master switch and the exclusion list together and answers both what may be read and what the watcher must let go of; `UndoPlanner` holds everything the undo hotkey decides before it touches the field. Eleven of the nineteen new tests fail against the reversion they cover.
- **The Windows tray app still ships unverified, and should be treated as a preview.** Everything under `apps/windows/src/LexiconBar.App/FixEverywhere/` uses UI Automation and `SendInput` to read and rewrite text in whatever application has focus. It compiles, and 214 headless C# tests run in CI on Linux and on `windows-latest`, but no part of the UI Automation half has ever been run on a real Windows desktop. CI cannot close that gap: a GitHub runner has no interactive session, so there is no focused element, no foreground window and no caret. That is why no release ships the binary. `docs/WINDOWS-APP.md` carries the `gh run download` line for the CI artifact, says which parts are reasoned rather than measured, and should be read before you grant this app anything.

### Fixed

- **Concurrent writes to the lexicon silently lost terms.** The rename was atomic but the read-modify-write around it was not, and five writers share these files: twelve concurrent `lexicon add` calls each printed `created TermN` and left one term behind. Every read-modify-write now runs inside a lock file taken with `O_CREAT|O_EXCL`. It works between processes, it is re-entrant so a nested `writeLexiconFile` does not deadlock, a lock whose owner pid has exited is broken at once (Ctrl-C and crashes), one nobody can attribute expires by age, and a writer that still cannot get in throws rather than overwriting. `recordHits` is the only caller that swallows that, because a lost hit count is bookkeeping and it may never throw by contract.
- **Three callers above the lock still read the lexicon, decided something, and wrote the whole document back.** The write took the lock, so the file always stayed valid and nothing ever looked broken, which is what let the lost update hide. `installPack` rewrote `settings.packs` from the snapshot the last `addTerm` returned, so a term someone else added during the loop was renamed away; `runInit` checked `existsSync`, wrote, then appended the example comment, so two inits racing both passed the check and an add landing between the write and the append was read back without the comment; and `runReview` merged against an already stale copy when a writer landed between its re-read and its write, while reporting success. `runReview` is locked only for the digest check, re-read, merge and write, because holding the file open for as long as someone reads their terms would block every other writer on a human.
- **One import of a non-UTF-8 file left the lexicon unparseable with no backup, and every message the product then showed was false.** `lexicon import` read every file as UTF-8. A UTF-16LE file, which is what PowerShell's `Out-File` and Notepad's "Unicode" option write, arrived with a NUL in every other byte and died against the schema naming the *destination* lexicon, so the error blamed a file the user had never touched. A Latin-1 file was worse: it imported with exit 0, no warning, and recorded `Caf<U+FFFD>` as the canonical spelling of a word with an acute accent, so a tool whose whole job is getting spelling right had stored the wrong spelling permanently and reported success. And the garbage was written before validation ran, with no backup, leaving a lexicon that `list`, `stats` and `add` all refused to read. `importers/encoding.ts` now decides the encoding from the bytes before any parser sees them: UTF-16 is unambiguous, from a BOM or from the NUL in every other byte, so it is decoded in either endianness and the PowerShell case simply works; an 8-bit encoding is not unambiguous, since Latin-1, Windows-1252 and KOI8-R are the same bytes meaning different letters, so it is refused by the name of the input file with the `iconv` and PowerShell commands that convert it. UTF-8 with or without a BOM comes back byte-identical to what `readFile(p, 'utf8')` returned before. `importLexicon` also refuses any term carrying U+FFFD, which covers callers that hand it a string rather than bytes. The serialized bytes now go through the reader's own parse-and-validate before anything is replaced, and the previous contents are kept at `<path>.bak`.
- **With a lexicon that would not parse, `doctor` told the user there were no terms and to run `lexicon setup`.** Both sentences were false: the file had terms, setup cannot repair a parse error, and running it exits 0 having done nothing. The MCP `lexicon_doctor` tool handed an agent the identical dead end with `ready: false`. A file that exists but will not parse is now its own verdict, ahead of the empty-lexicon one, quoting the parse error and pointing at `lexicon edit`. Both the check line and `nextStep` lead with their command, because rendering caps a line at 200 characters and an absolute path can eat most of it.
- **`lexicon normalize` printed the parse error to stderr and exited 0 with the text unchanged**, which made "no corrections were applied" and "nothing needed correcting" the same answer. stdout still round-trips the input byte-exactly, because a broken lexicon must not damage a pipeline, but the exit code is 1.
- **The hook went quiet instead of saying the lexicon was broken.** A file that does not parse threw all the way out to `main()`, which writes one line to stderr and exits 0. Through Claude Code that line goes nowhere anybody looks, so corrections simply stopped and nothing said why: the user's first clue is that their company name is wrong again. The problem now goes out through the one channel the hook is already allowed to use. It tells the agent the file does not parse, quotes the parse error and names `lexicon edit`, on both hook events. The hook still exits 0 and still never touches the prompt.
- **`voice --toggle` deleted finished recordings.** Every toggle capture is spawned with `-t 600`, so a recording nobody stops ends itself at ten minutes. The next press then found a pid that was gone, called the state stale, deleted the WAV without ever opening it, printed "recording" and exited 0. A complete, finalized ten-minute capture was removed unread. A recorder that is gone is now inspected before anything is decided: the audio is transcribed whatever killed the recorder, with the length taken from the bytes rather than from a wall clock that counts the time the recorder was dead, and a capture with nothing usable in it is reported with ffmpeg's own last lines and the microphone-permission hint.
- **Four further ways a recording was thrown away on a guess.** A capture was deleted before anyone knew whether anything had been heard, because `cleanTranscript` turns `[BLANK_AUDIO]` into the empty string and so does a wrong `--lang` or a model too small for the speaker: a ten-minute 19.2 MB capture reached exit 3, `(nothing heard)` and an empty directory. `recoverDeadRecorder` could delete the WAV of a recorder that was still running, because a per-pid lookup that says "not yours" about a live pid is one command line read back and PowerShell folds a long one exactly where the capture's path sits. "An empty process list means cannot tell" was documented and not honoured, so on a host with no `ps` five minutes of live audio was abandoned under a second recorder. And the RIFF pad-byte walk stepped to the padded offset first, where one byte into a real id reads as printable ASCII often enough to refuse 48 of 128 capture sizes, swept rather than sampled. Nothing deletes a capture that holds bytes any more; `discardOrKeep` removes only a zero-byte placeholder.
- **A recycled pid could send the stop signal to a stranger's process.** A pid is unique only while its process lives, and `isAlive` cannot tell a stale state file from a live recorder. A start that died between spawning ffmpeg and writing the pid down also left a recorder nothing could stop, and the old code cleared the state and started a second one, so two competed for the microphone until the first reached the end of its own `-t 600`. `makeProcessDescribe` and `makeProcessList` read the process table through the existing exec dependency, `ps` on Unix and `Get-CimInstance` on Windows, with a literal filter so no caller-supplied path is ever interpolated into a shell. A live pid is confirmed before it is signalled, an orphan is found by the capture it is writing and transcribed rather than abandoned, and where the process table cannot be read at all both fall back to trusting the pid.
- **On Windows every toggle recording under about eight seconds was lost outright.** ffmpeg buffers 256 KB, so a capture killed early left a zero-byte file rather than a truncated one. Measured against ffmpeg 9.0.2. `-flush_packets 1` fixes it, the stop no longer claims to have finalized the WAV header when it cannot (Node maps every signal to `TerminateProcess`, and a detached recorder stopped by another process shares no console, so a real interrupt cannot be delivered), and the WAV check parses the container instead of trusting a size above 44 bytes.
- **The Windows write path could leave half a correction in a field with no undo and tell the user the write had failed.** `Keyboard.Send` issued one `SendInput` per 400 INPUT records, which is 200 characters, while the comment above the loop claimed the non-interleaving guarantee a single call gives. A later call failing left the earlier ones in the field, the engine found the field no longer held what the plan was made from, tripped its guard and reported "field changed" while half the replacement sat there, the user's own span was gone and `_undo.Record` had never been reached. There is one `SendInput` per write now, never a loop, capped at 1000 key events, with backspaces and their retype in the same call so the deletion can no longer succeed alone. A replacement longer than the cap goes through `ValuePattern.SetValue`, which replaces the whole value in one call and cannot half-finish. `Type` and `ReplaceTail` return how much landed rather than a bool, and `PartialWrite` computes what the field must hold when n of m key events landed. Undo consumes its ledger entry only after the write succeeds; it used to take the entry first, so an undo that did nothing threw away the only record of the correction.
- **The macOS write path had the same bug and a worse shape.** The keystroke rung posted CGEvents in chunks of twenty UTF-16 units and accounted for none of it: a chunk whose CGEvent came back nil was skipped in silence while the chunks after it went out anyway, so a failure in the middle left a hole in the middle. `UnicodeTyping.post` now builds both key events for a chunk before it posts either and stops at the first chunk it cannot build, and chunk boundaries step back off a surrogate pair, so what landed is always a prefix and every stopping point is a whole string.
- **The recovery for a half-written correction was racing the keystrokes it recovers.** `SendInput` and CGEvent posting both queue, and the target app consumes on its own message loop, so the count that comes back is records inserted rather than characters consumed. The partial-write path took one immediate reading and demanded it equal the single state the count predicted, so the two likeliest outcomes were both wrong: if the app had not started on its queue the field looked untouched, the whole-value write went ahead and the queued characters landed on top of it, and if the app had consumed a different number the engine answered that it could not account for the state and recorded nothing. `KeystrokeSettle`, in the portable core on both platforms, watches the field across the same 0.6 s window the success path waits out and identifies the state from what the field holds rather than from what the count claimed, keeping the count only as a bound on how much can have arrived. A half-landed write then falls through to the whole-value write, which repairs it, and where that cannot run the ledger gets an entry describing the half-written state before the user is told anything, so undo puts their own text back and the message says only part of the correction went in. Keystrokes the system accepted that never appeared are deliberately not written over, and the state they would produce is recorded so a late arrival is still reversible. On macOS, `undo.take` cleared the ledger entry before the write was attempted, so an undo whose write did nothing threw away the only record of the correction; the entry is consumed on success only.
- **The setup wizard's repo harvest was teaching the lexicon to rewrite ordinary English.** Step 3 ranked PascalCase symbols by how often they appear in source and generated each one an alias by splitting the camel case, so `InlineData` arrived carrying `inline data` and `TimeInterval` carrying `time interval`, and from then on "let us set a time interval of five minutes" came back with a class name in it. Measured over forty-five ordinary dictated sentences across four repos, the list this step builds by default damaged 5.0% of them and the twenty-name version 10.6%. `harvestRepo` stops inventing word boundaries: an identifier gets no aliases at all, and a name without a separator of its own keeps only the single-word suggestions, so "Ashlr.AI" and "pasture-notes" keep "Ashlr AI" and "pasture notes" while "Lexicon Bar" is gone because "LexiconBar" never said where its words break. The ranking was wrong too: a name is proposed only when the repo says it somewhere other than its own source, which means a manifest, a README sentence, the git log, the directory name or a dot-TLD brand. With the symbol flood gone the wizard's minimum count of five was only hiding real names, so it drops to two, and a three-file project that used to yield nothing but its own directory name and the git author now finds four of the five services it actually runs on. Same corpus after the change: 0.6%, and the one remaining case is this repo's own LexiconBar, a real product name matched phonetically rather than through a generated alias.
- **Text that quotes a misspelling is no longer flattened into one spelling.** The hook rewrote "the chips Mason Wiatt / Mason Wyat" into two copies of the canonical, and the sentence stopped saying anything. That matters well past one report, because the lexicon file, the docs tables, the onboarding screen and any conversation about which words to add all quote the misspellings on purpose. The obvious rule, never collapse two spellings into one, is wrong: "the reddis and red iss instances are the same box" is one person dictating one word twice and both halves must be fixed. The guard was built, reviewed, rebuilt, reviewed and rebuilt again, and the final version asks a closed question rather than an open one. The gap between two mentions must be made *only* of words about writing rather than merely contain one, so a single word about the world ("caching", "upgrade", "scripts", "again") makes it dictation whatever cues sit beside it; a lead-in counts only when the passage opens with it; the canonical anchors in any spelling that folds to it, so "it's ashlr.ai, not Ashler" survives; a single newline no longer ends a passage, which had silently disabled the guard for every markdown list and YAML block it exists to protect; and the refusal is per run of linked mentions rather than per block, because sentence bounds cannot be got right when a period follows a digit or an abbreviation.
- **The quoting guard is now pinned by a generated suite rather than by hand-picked lists.** Both earlier versions tested whether a cue word sat *somewhere near* the mentions, first anywhere in the sentence and then anywhere inside a thirty-character gap, and "somewhere near" is an open test when `not`, `heard`, `wrote` and `means` are ordinary English. `tests/enumeration.property.test.ts` generates the round trip from parts: 56 connectives in both orders, three canonical spellings per term, quoting, prose wrapping, tables, YAML, markdown lists and multi-line blocks, mirrored by ordinary dictation and by every quoting shape with the canonical removed. Quoting must keep both spellings, dictation must lose the garble, and neither number can be traded for the other in silence. Against the guard as it stood, 27,873 of 36,540 generated quoting cases failed and 24 of 243 dictation cases failed. It now passes 36,540 of 36,540 and 243 of 243, with nothing skipped. Both benchmarks were run and neither moved, which is the point: the corpus cannot see any of this. The guard also walked every span for every sentence, which was quadratic on the 1 MB the local API accepts; one moving cursor now costs 59 ms.
- **Two spans the matcher was widening past the word it matched.** A phonetic window grew one token past the garble whenever the extra token made no sound of its own. Phonetic confidence is a ratio of letter counts, so a bare numeral costs nothing at all and a two-letter abbreviation costs almost nothing: the wider window stayed above the threshold and then won overlap resolution on span length. "cooper netties i.e. Terraform" came out as "Kubernetes. Terraform", and "1. cooper netties 2. Cooper Netties" lost the 2. An inexact multi-token window now never starts or ends on a numeral or a spelled-out abbreviation. The guard is lexical rather than phonetic because scoring cannot tell these cases apart: a trailing "ai" adds nothing to a metaphone key either, so refusing every window whose edge token adds no key would lose "opin ay" to OpenAI and "ashlur ay" to Ashlr.AI. It is the phonetic pass only, since "b 2 b" and "auth 0" are aliases users list and the fuzzy pass compares only windows of the same token count.
- **Indented code blocks are skipped now.** `skipCode` did not know Markdown's other code block, a run of lines indented by four spaces or a tab, so the hook rewrote the indented repro inside a bug report about the bug above. The rule is deliberately narrower than CommonMark: a block needs a blank line above it and a column-zero, non-list, non-quote line above that, so a wrapped paragraph line, a list item's indented continuation and a nested bullet stay ordinary text. Indented code inside a list or a block quote is still corrected.
- **The landing page told visitors this was version 0.5.0** while `package.json` said 0.5.2 and npm served 0.5.1: three numbers live at once for a project whose pitch is getting details right. The version check only ever matched `#vX.Y.Z` pins, so a version written as a constant was invisible to it, which is how `web/lib/site.ts` drifted two releases behind without anything noticing.
- **The README's "How it works" block printed output the command does not produce.** It showed "cooper netties" resolving through the phonetic tier at 0.85, but that string is an explicit alias in the developer pack, so it never reaches that tier: the real answer is alias at 1.00, and the block was illustrating a tier with an example that skips it.

### Changed

- **Step 3 of `lexicon setup` defaults to no.** It is a write inside the user's repository plus a trust decision, offered ninety seconds in, to someone who cannot yet judge the list. Saying no costs one command later. `harvest --symbols` brings back the uncorroborated source symbols for reviewing one at a time.
- **`lexicon setup --dry-run` describes a run that can actually happen.** It was reporting the starter packs and the harvest as things it would do, which `--yes` alone never does, while reporting steps 5 and 6 as skipped when a real run asks to install a launchd login service and to write a CSV to the Desktop. The plan now reasons about the run it describes rather than about itself: `plan.interactive` says whether that run would find a terminal, `plan.wouldAsk` names the steps that are questions, and each prints as "asks" with the answer Enter gives it.
- `bench/run.ts` wrote `bench/results.json` on every run, including ablations, and `bench/README.md` tells contributors to commit that file after a matcher change. A run of `--no-phonetic` followed by a commit therefore published a non-default number as the headline one, which is how `BENCHMARK.md` drifted in the first place. A run that overrides the config now refuses the default path and asks for `--out`.

The prompt row is a complement rather than a rival and is described as one, since stacked with the lexicon it reaches 95.7%.

- The product imagery on [lexicon.ashlr.ai](https://lexicon.ashlr.ai): nine captures that were serving but referenced by nothing, now placed, all lazy, each declaring its own dimensions so the page does not move as the bytes arrive. An `IntersectionObserver` drives the clips, because Chrome pauses a recording that is off screen and both clips mount below the fold, so the fix-in-place clip used to run for a sixth of a second at load and sit on that frame forever. The brand wall gets a fixed leading slot on every tile, a CC0 mark where one is licensed and a monogram in our own mono face where none is, because ten of the thirteen brands may not carry a logo at all and uniformity had to come from the treatment rather than from sourcing.

### Internal

- **The committed plugin bundle carried 695 absolute paths to a maintainer's home directory.** That happens when the bundle is built in a tree whose `node_modules` is a symlink: esbuild then names every bundled module by the path it resolved to rather than by `node_modules/...`. It has been committed before. Build with a real `node_modules` inside the build root, and `grep -c /Users/` the output before committing it.
- 927 TypeScript tests (was 858 at 0.5.2), 228 Swift (was 175) and 214 headless C# (was 144).
- `docs/CONTRACT.md` had not caught up with either the lock or the recorder work. It still said `writeFileAtomic` was the whole story, which was the mistaken idea that caused the lost update: atomicity means a reader never sees half a file and says nothing about two writers each writing its own idea of the result. It now carries `withFileLock` and `withLexiconLock`, what the lock does about a crashed owner, that validation checks the serialized bytes rather than the object, and `inspectWav`, `WavCheck`, `discardOrKeep` and the Windows stop that cannot be graceful. It also names the read-modify-writes that were still outside the lock at the time, because a partial fix that reads as a complete one is how the next person inherits this.
- **Two over-claims in the comparison table's prose, both found by review.** "Worth 20 points" and "worth 29 points" attributed the whole gap over exact substitution to the phonetic and fuzzy tiers, when those are deltas against baseline rows: the repo's own by-reason tables size the tiers at 11.1 points on small.en and 8.6 on base.en, and the rest is case-insensitive matching of the canonical (9.3 points) and the alias tier's tolerance for how the recognizer splits a name (8.6). And "the two baselines that do nothing cannot wrongly change prose" is true of raw whisper.cpp and false of `--prompt`, because prompt hints bias the recognizer itself, so the damage is in the transcript before anything scores it while this metric counts only what a post-pass altered. That cell is unmeasured rather than zero, and the pages say so.
- **A claim made in that correction was withdrawn on the page rather than quietly edited out.** Two clips were offered as proof that prompt hints damage prose. A second review checked them: they are term-carrying positives where the word in question is the expected term, not prose negatives, and one reads the same way with no prompt at all. The correction was right about the metric and wrong about the evidence.
- **`docs/BENCHMARK.md` stated a headline term precision its own configurations table contradicted**, and a prose false-positive rate three revisions old. Every table is regenerated from the current matcher: precision 95.0% (302/318), F1 95.7%, prose false positives 12.5% (15/120) and 0 of 95 excluding the adversarial cases. The audio figures in `README.md` and `ENTERPRISE.md` moved too, and not because of any guard: they had not been regenerated since the step G precision guards landed, so recall on base.en is 82.8% rather than 86.4% and the prose false-positive rate 16.7% rather than 20%. The guards bought precision with recall and the docs were quoting the half that flattered. The site keeps its own copy of those numbers, so `web/app/page.tsx` and `web/lib/llms.ts` were serving the old recall as well, the second of which is what agents read when they decide whether to recommend this.
- 205 em-dashes and en-dashes removed across `docs/`, along with a sweep of contradictions a stranger would hit: the FAQ and `AGENTS.md` told the reader Windows and Linux had only the CLI, MCP server and extension, omitting hooks, the plugin, the local API, the daemon and exports, all of which CI tests there; `TEAM-SYNC.md` named a `LEXICON_CONFIG` variable that does not exist; and `ENTERPRISE.md` claimed a product in production that `COMMERCIAL.md` says has no known users.
- `check-facts.mjs` now reads a declared `VERSION` constant as well as a `#vX.Y.Z` pin, which is the drift that let the landing page sit two releases behind. The word boundary keeps sentinels like `UNKNOWN_VERSION` out.
- `docs/RELEASING.md` gains the two traps that cost time cutting 0.5.2: `git tag -a`, because `--follow-tags` pushes annotated tags only and a lightweight one is created locally, silently not pushed, and the release workflow never fires; and publishing by hand *without* `--provenance`, because `libnpmpublish` branches on `GITHUB_ACTIONS` and `GITLAB` and throws `EUSAGE` for anything else before it ever reaches the registry.
- The `.bak` and `.lock` a lexicon write now leaves beside itself are gitignored, along with `.vitest/` and `web/tsconfig.tsbuildinfo`, which was tracked and turned up dirty in every status.
- `resolveScopeWritePath` is exported, so a caller doing several writes as one operation can lock the path `addTerm` will pick rather than resolving it a second way and getting a second chance to disagree.

## 0.5.2 (2026-09-20)

Windows and Linux are in CI for the first time, running the real platform tools rather than fakes. That found a bug that had been breaking every Windows install since the hook existed, and a test that had never tested the thing it claimed to.

### Security

- **`lexicon install claude --apply` on Windows wrote a hook command pointing at a file that does not exist, and reported success.** `launchCommandLine` quotes the hook path and escapes the characters a POSIX shell would otherwise eat, and the backslash is one of them. On Windows the backslash is the path separator and nothing else, so `C:\Users\me\...\hook.js` went into `settings.json` as `"C:\\Users\\me\\...\\hook.js"`. Every `lexicon install claude --apply` on Windows has been doing this for as long as the hook has existed: the correction hook was never actually installed, while the CLI said it was, and nothing downstream noticed. Quoting on Windows now escapes nothing, which is safe because a Windows filename cannot contain a `"`, and escaping `$` or a backtick would corrupt a path that legitimately holds one. The platform is a parameter rather than read off the host, and the absolute-path check uses `path.win32` so it answers for the OS being targeted.
- **The printed `claude mcp add` line carried the same defect.** `cmd-install.ts` holds a second copy of the POSIX quoting, used for the instruction printed when `--apply` is not given, so the command a Windows user copied out of the terminal named `"D:\\x\\dist\\mcp\\server.js"` rather than the file. Same fix and same reasoning. `quoteArg` was also handed to `Array.map` bare, so the array index arrived in its `platform` argument.
- **The test asserting that term harvesting never reads `node_modules` had been passing without asserting anything.** `harvestRepo` walks a user's repository to propose terms, and `node_modules` is on its always-ignored list. The fixture that proves the skip lives under a `node_modules/` path, so a contributor's global gitignore kept it out of `git add` and it was never committed: CI cloned a fixture with no vendored file in it, harvest had nothing to skip, and the assertion passed for the entire life of the test. For a tool that reads your code, "it does not look in there" is a promise that has to be exercised, and this one never was. The fixture is force-added, and both tests now read it and assert it is present before asserting it was skipped, so if it goes missing again they fail loudly instead of going quiet.
- **The Windows tray app ships unverified, on purpose, and should be treated as a preview.** Everything under `apps/windows/src/LexiconBar.App/FixEverywhere/` uses UI Automation and `SendInput` to read and rewrite text in whatever application currently has focus. It compiles and its decision rules are tested headlessly, but no part of it has ever been run on a real Windows desktop. CI cannot close that gap: a GitHub runner has no interactive session, so there is no focused element, no foreground window and no caret. Read `docs/WINDOWS-APP.md` before you grant it anything.

### Added

- **A Windows tray app** under `apps/windows/` (C#, .NET 8), built and tested from a Mac. `LexiconBar.Core` targets plain `net8.0` and may not reference UI Automation, WinForms or Win32, which is what lets its xunit suite run headless on a machine that cannot launch the app at all. ### Changed

### Fixed

- **A fuzzy match turned "remind" into "Rewind".** Twenty-two ordinary English words around reboot, refund, remind, rename, rewind and rewrite were missing from the matcher's stoplist, so any lexicon holding one of those as a brand would rewrite plain English in a user's sentence. Found by recording the product, which puts the whole thing in front of you at once and is a better test than any suite. The clean-sentence benchmark is unchanged at 0 false corrections in 95 sentences.
- **The LexiconBar status item can no longer end up invisible.** The reported "icon does not render in the menu bar" turned out not to be an app bug: on the machine it was found, the main display had a fullscreen window over it, so that display's menu bar was slid out of view and *every* status item on the Mac reported a y of -59, LexiconBar's and fifteen other apps' alike. A throwaway app with three textbook status items, one carrying nothing but a plain text title, was equally invisible under the same conditions, and a text title cannot fail to draw, which is what rules the app out; the second display's narrower menu bar drops its leftmost items, and LexiconBar is the leftmost, so it was missing there too. - `NSImage(systemSymbolName:)` returning nil for a renamed or withdrawn symbol on a future macOS would previously have left the button with no image *and* no title. It now always has one or the other.
- **Every production deploy of [lexicon.ashlr.ai](https://lexicon.ashlr.ai) had been failing.** Four separate causes, each of which hid the next. The Vercel project had no Root Directory set, so every push built from the repo root, ran the root `prepare` script and then failed with "No Next.js version detected"; it is `web` now, which is also why deploys must be run from the repo root rather than from inside `web`. `web/package.json` did not declare the four runtime dependencies the demo bundle pulls in through `src/core` (`double-metaphone`, `fastest-levenshtein`, `yaml`, `zod`), because they had only ever been resolved from the root install. esbuild resolves a bare import upward from the importing file, so a matcher under `src/core` looked in the root `node_modules` and never in `web/node_modules`, which is the only one Vercel now installs; both build calls get explicit node paths. And `lib/generated` is gitignored while only `build-demo-bundle` ran in `prebuild`, so the media manifest existed on one machine and nowhere else and every git-triggered build failed typechecking on an import of a file it had no way to produce. Proved by deleting `lib/generated` and building from empty.
- `lexicon voice --model ~/...` resolved against the wrong directory on Windows. The tilde was expanded with `process.env.HOME ?? ''`, and `HOME` is undefined there (it is `USERPROFILE`), so the path silently became relative to the cwd and the model was reported missing wherever it actually was.
- `XDG_CONFIG_HOME` was read four different ways with three different empty-value semantics, two of them with `??`, so `XDG_CONFIG_HOME=""` produced a *relative* config path. Unset, blank and relative all fall back now; absolute wins.
- `which.ts` joined its well-known-directory candidates with the host's `path.join` while the PATH scan used the injected platform's flavour, so the two halves of the same lookup could give different answers.
- The Homebrew formula was two releases behind, and 0.3.2 cannot parse a lexicon written by 0.5.x at all: the pack source is unknown to its schema, so it refused the file with 108 validation errors. Anyone who installed through brew and then ran `lexicon setup` had a broken tool.

## 0.5.0 (2026-09-20)

### Added
- **A landing page at [lexicon.ashlr.ai](https://lexicon.ashlr.ai).** `web/` is a Next.js site with a live in-browser demo: the same matcher the CLI runs, bundled for the browser by `web/scripts/build-demo-bundle.mjs`, so a visitor can type a garbled sentence and watch it get corrected without installing anything or sending a keystroke anywhere. See docs/LANDING.md for the deploy.

### Fixed
- **`lexicon doctor` could name a different whisper binary than `lexicon voice` would actually run.** The sync PATH lookup iterated directories in the outer loop and candidate names in the inner one, while the async lookup did the reverse, so on a machine with `whisper-cpp` in `/opt/homebrew/bin` and `whisper-cli` in `/usr/local/bin` doctor reported one and voice ran the other. Both forms now use name-preference order: every PATH entry is tried for the first candidate name before the second name is considered at all. The two are unified in `src/util/which.ts` and `tests/which.test.ts` asserts they agree.
- **Streamed dictation was dropped entirely.** macOS's own dictation, Wispr Flow's streaming mode and an app's built-in microphone button do not paste a finished phrase: they insert a word at a time. The gaps between spoken words are routinely longer than the 700 ms settle delay, so each word ended its own run, was judged `too short (1 words, N units)` and was thrown away — then so was the next, and the next. Measured live in TextEdit with words arriving 900 ms apart: nine consecutive skips and a sentence left completely uncorrected, while the same words arriving 250 ms apart were corrected normally. The feature only ever worked for paste-sized insertion, which is a much narrower promise than "works with any dictation". `BurstDetector` now separates a verdict from acting on it: a run that has produced at least one word-sized insertion is held open (`Outcome.coalescing`, and the baseline does not move) until the field has been quiet for `runQuietMs` (default 1500 ms — longer than a pause between words, shorter than the end of a sentence), so the words accumulate into one burst and are corrected together. `maxRunMs` (default 12 s) caps a run so continuous dictation is still corrected periodically. Two things keep this from swallowing ordinary input: key-by-key typing never produces a `minChunk`-sized insertion, so it is still refused with `typed, not dictated` however slowly it is typed; and a single insertion that already reads as a burst is a paste with nothing to wait for, so it still fires at the settle delay. Verdicts that silence cannot change — multi-paragraph, field too long, an insertion point that cannot be located — are refused immediately as before.
- **Fix everywhere did nothing in the Codex (ChatGPT) desktop app.** Dictating into its composer left `My company, Ashler, deploys Stéphan Versel.` uncorrected, with no log line at all, because LexiconBar never saw a text field there: the app answers `kAXErrorNoValue` for `AXFocusedUIElement` and its whole window reads as six nested empty `AXGroup`s. It is Chromium-backed but rejects `AXManualAccessibility` (`kAXErrorAttributeUnsupported`), the switch Electron uses and the only one LexiconBar sent. Writing AppKit's `AXEnhancedUserInterface` instead wakes it, and the composer turns out to be an ordinary `AXTextArea` with `AXValue`, `AXSelectedText` and `AXSelectedTextRange` all settable — so this was never a field we could not write, only one we could not see. `FocusWatcher` now sends that second nudge, and the same burst is corrected in place: `My company, ashler, deploys on versal and cuban eats` → `My company, Ashlr.AI, deploys on Vercel and Kubernetes`, via the keystroke strategy in 299 ms. What actually wakes the app is the request rather than the attribute — the write reports `kAXErrorNotImplemented` and the tree appears anyway, while the 500 ms focus poll had been reading the same app for minutes without waking it — so the error code is logged rather than acted on. The nudge is sent only to an app that has already reported no focused element, at most once per process, because where the attribute *is* honoured enhanced mode makes AppKit animate window frame changes. Cursor and VS Code remain invisible even after it, and now say so in the log rather than failing silently.
- **Fix everywhere could corrupt text it was asked to correct.** Seen live in TextEdit: a document holding "ping Ashlr.AI about the cooper netties rollout" received the burst "ping ashler about the cuban eats rollout on versal" in front of it and ended up as `ping ashler about the cKubernetes rollout on versalping Ashlr.AI about the cooper netties rollout` — the replacement one character late, the leading `c` of "cuban" orphaned, and the other two corrections in the same burst missing entirely. The cause was in the pure diff: `TextDiff.delta` locates an insertion by stripping the common prefix and suffix, and both strings begin "ping ", so those five units were credited to the old text and the reported window started five units late and ran five units into text the user already had. The window was textually consistent — `substring(fullText, range) == burst.text` held — so every downstream guard passed and the rewrite was spliced across the boundary. `delta` now also measures how far the window could slide and still produce the same result (`slideLeft`, `slideRight`) and takes an optional `caretEnd`, the insertion point, which picks the window that actually arrived (`anchored`). `BurstDetector.settle(at:caretEnd:)` takes the caret from the focused element and refuses outright — `skipped("insertion point is ambiguous")` — when the insertion cannot be located and nothing pins it down: no correction is much better than a correction spliced into the middle of someone's sentence. The check runs last, so ordinary skips keep their real reason.
- **Fix everywhere now refuses to write into a span it has not verified.** The rewrite selects the burst range and writes `AXSelectedText`, trusting the app to mean the same UTF-16 offsets. It now re-reads `AXValue` immediately before the destructive write (the range round-trip polls for up to 300 ms, and the field is live throughout), and reads `AXSelectedText` back after selecting: unless the selection holds *exactly* the text the plan replaces, the two range strategies are skipped and the whole-value write takes over, which is computed from the pre-write snapshot alone and so cannot be misaligned. The same check is repeated immediately before the keystroke strategy. A write that lands but produces something other than the plan leaves the field alone rather than writing again on top of it, and says so. 13 new tests in `LexiconBarKit` covering the exact corrupting shape, caret anchoring, a caret that cannot be believed, slide measurement in both directions, several replacements in one burst with the user's own text on both sides, a stale snapshot and a burst range that no longer holds its text.
- **The macOS Accessibility grant survives a rebuild.** TCC binds a grant to the app's designated requirement, and an ad-hoc signature has no certificate to name the app by, so the requirement was `cdhash H"…"` — a different value on every build. The row in System Settings kept its switch on while tccd denied the app with `Failed to match existing code requirement for subject ai.ashlr.lexiconbar`, and toggling the switch did not rebind it; only removing the row with **−** and adding the app again did, once per build. New `scripts/make-signing-identity.sh` creates a self-signed code-signing certificate in a keychain of its own — `LexiconBar Local Signing`, RSA 2048, ten years, `basicConstraints=critical,CA:false`, `extendedKeyUsage=codeSigning` — and `scripts/build-macos-app.sh` signs with it when it is there. The requirement becomes `identifier "ai.ashlr.lexiconbar" and certificate leaf = H"<cert>"`, which depends on the certificate rather than on the bytes, so it is byte-identical across builds: two builds of a genuinely different binary (cdhash `e0184aa0…` then `1fdb6b1b…`) produced the same line, and the second satisfied the first's requirement under `codesign --verify -R`. Grant it once and every later build is still the same app to TCC. See docs/MACOS-APP.md.
- **LexiconBar `--status` told the truth about Accessibility.** `AXIsProcessTrusted()` answers for the *responsible process*, which for anything started from a shell is the terminal, so `--status` inherited the terminal's grant: a freshly built `.build/release/LexiconBar`, a binary that cannot hold a grant of its own, reported `axTrusted: true` at the same moment the unified log showed the GUI-launched bundle being denied (`kTCCServiceAccessibility auth_value: 0`). The one person most likely to run `--status` — someone debugging why Fix everywhere does nothing — was told the opposite of the truth. A terminal-launched run now refuses to answer for itself: the text form prints "Accessibility: cannot be checked from a terminal (this process inherits the terminal's grant)", and the JSON reports `"axTrusted": null` with the inherited value kept as `axTrustedRaw` and the reason as `axTrustedNote`. Launched by the window server it reports `AXIsProcessTrusted()` as before. "Terminal-launched" is decided by the parent process (a window-server launch is parented to launchd) *and* by a controlling terminal, because a shell script, a CI job and an agent harness all run with pipes and no TTY and still inherit the shell's grant — `isatty` alone was tried first and reproduced the original bug from a pipe-only shell.
- **LexiconBar now answers the Accessibility question from a terminal, honestly.** The running app writes its own trust state, pid and a timestamp to `~/Library/Application Support/LexiconBar/state.json` (mode 0600, written to a temporary file and `rename(2)`d into place) at launch, when the focus watcher starts or stops, when the grant changes under it, and every 30 s otherwise. `--status` reads it and prints a second line — `Accessibility (menu bar app): trusted|not granted (as of <relative time>)` — falling back to "not running" when the file is missing, when it carries the `running: false` record written on quit, or when it is more than 5 minutes stale. `--status --json` exposes the same as `axAppTrusted`, `axAppRunning`, `axAppStateAge`, `axAppStatePath` and `axAppStatus`; `axAppTrusted` is what a script or an agent should read. The exit code follows whichever answer is real.
- LexiconBar quit cleanly on SIGTERM. AppKit runs `applicationWillTerminate` for the Quit menu item but not for a signal, so `kill` and a logout took the app down with none of its cleanup: the `lexicon daemon` and `lexicon serve` children outlived it, and the new state file was left claiming the app was up until it aged out. A `DispatchSourceSignal` now routes SIGTERM through `NSApp.terminate`, so both paths run the same shutdown.
- LexiconBar first-run window: the Accessibility status line now warns about the signature trap. Rebuilding an ad-hoc signed app changes its code signature and the existing System Settings entry stays bound to the old one — the switch reads "on" while TCC denies with `Failed to match existing code requirement` — and toggling it does not rebind it. The hint says to remove the entry with **−** and add the app again.
- **LexiconBar told the truth about who runs the local API.** The menu's **Local API** checkbox and the first-run window's "Local API at login" row only ever reflected whether *the app* was supervising its own `lexicon serve` child — one of four ways the server can be up. On a machine where the launchd agent `ai.ashlr.lexicon.serve` owns it (what `lexicon serve --install` writes), both read "off" while the API was plainly answering on `127.0.0.1:41733`, and ticking either would have started a second server that cannot bind the port. A new pure `ServeOwnership` resolver in `LexiconBarKit` turns four observable facts — `launchctl print gui/<uid>/<label>` exit status, whether the plist is on disk, whether `GET /health` answers, and whether this app's supervisor has a live child — into one of `launchAgent(label:programPath:)`, `appChild`, `foreign` or `none`, plus the words the UI shows. launchd wins outright (`KeepAlive` takes the port back regardless), then our own child, then a stranger on the port, then nobody. The menu row and onboarding step 4 read the same resolver, so they can never disagree: a LaunchAgent gives a non-toggle status line, "Local API: running at login (launchd)", with a "Manage with `lexicon serve --uninstall`" hint and no checkbox to start a duplicate; a foreign listener gives "Local API: reachable (not managed by this app)"; and only `appChild` and `none` are clickable.

### Security
- **A hostile repo could read text into your agent through the tool that exists to stop exactly that.** The trust model tells an agent to call `trust_project` rather than open an unreviewed `.lexicon.yaml` itself, so the file's contents never reach the conversation. A file that failed to *parse* defeated it: the `yaml` package embeds the offending source line verbatim in its error message (`prettyErrors`, on by default), and `trust_project` returned that message unsanitized. A repo could put instructions on the line before a deliberate syntax error and have them read into the agent's context the moment it did the safe thing. Escape sequences and bidi overrides in the *path* leaked the same way, through the file path, the registry path and the summary strings, which were echoed raw. Every string the tool echoes now goes through `sanitizeForDisplay`, on the throwing branch as well as the returning one. `tests/mcp-trust-injection.test.ts` runs the real server against a real hostile file on disk rather than a mock, because the leak lived in the seam between the YAML parser and the tool result.
- **Fix everywhere reached into password managers it did not exclude.** The default exclusion list named only Terminal, iTerm2, Warp, Apple Passwords, 1Password and Keychain Access, while docs/MACOS-APP.md claimed flatly that "password managers are excluded by default". Bitwarden, Dashlane, LastPass, KeePassXC, NordPass, Enpass, Proton Pass, Keeper, RoboForm and Strongbox were all missing, and the secure-field check only refuses the literal masked input — so in any of them an item's notes, a custom field holding a secret, a TOTP seed box or a vault search field echoing a saved username was fair game, and Fix everywhere is on by default. The list now covers those managers (mostly as vendor prefixes, because an exact list is wrong the moment a vendor ships a new bundle id — Keeper alone has shipped under `com.callpod.*` and `com.keepersecurity.*`) and more terminals (Ghostty, kitty, Alacritty, WezTerm, Hyper). A bundle-id list always lags reality, so there is now a second, id-independent guard: new `SecretFieldHeuristic` in `LexiconBarKit` refuses a field whose accessibility identifier, placeholder, title, help, description or role description — or the title of its window — contains any of `password`, `passphrase`, `secret`, `token`, `api key`, `private key`, `seed`, `mnemonic`, `recovery`, `pin`, `cvv`, `security code`, `otp`, `totp`, `2fa`, `credential`, `keychain`, `vault`, `card number`, `social security` and friends, in any app. Matching is on whole words after splitting camel case, snake case and punctuation, so `apiKeyField`, `api_key` and "Recovery phrase" match while "shipping" never matches "pin", "tokenizer" never matches "token" and an ordinary Notes field is left alone. Both refusals now happen when focus lands rather than when a burst is ready, so a field in a vault is never watched and no snapshot of it is ever held: the log says `not watching com.apple.Terminal: excluded` or `not watching this field in <app>: it looks like it holds a secret (recovery)`. Verified live: an ordinary, unmasked `<textarea aria-label="Recovery phrase">` in Safari is refused while an unlabelled one beside it is still corrected. docs/MACOS-APP.md now lists exactly what is excluded and how to add your own app's bundle id.

### Internal
- **`src/` grew a bottom layer and lost about eighty copy-pasted helpers.** Seven waves of parallel agents had each written their own error formatter, PATH lookup, atomic write, JSON config editor and version reader. There is now one home for each: `src/util/{errors,json,which,atomic,package}.ts`, plus `src/cli/io.ts` for everything the CLI prints through. Four files that had become grab bags split along real seams with their public import paths preserved by re-export, so no caller changed: `commands.ts` into `io.ts` + `claude-settings.ts` + `cmd-doctor.ts` + `cmd-install.ts`, `mcp/server.ts` into `mcp/shared.ts` + `mcp/tools/*`, `cmd-setup.ts` into `cli/setup/*`, and `core/matcher.ts` into `core/matcher/{build,text,tokenize,tuning}.ts`. `whichBin` is gone; use `findOnPathSync`. `isProjectTrustError` is exported from `src/core` for callers that cannot use `instanceof`. The benchmark is identical before and after. docs/CONTRACT.md is rewritten for the new shape.

### Security
- CLI output is sanitized against terminal escape injection: paths, canonicals, aliases, notes, harvest evidence and quoted error text pass through the new `sanitizeForDisplay`; `renderTable` sanitizes every cell. `normalize` stdout is unchanged.

- Project `.lexicon.yaml` files are skipped until approved with `lexicon trust` (preview, sha256 pinned in `<config dir>/trust.json`; `lexicon trust --list`, `lexicon untrust`). A changed file drops back to untrusted until re-trusted. `LEXICON_TRUST_ALL=1` bypasses the gate for CI. `loadLexicon()` takes `includeUntrusted` and reports `projectTrust` / `skippedProject`; `list`, `normalize` (`--include-untrusted`) and `doctor` warn; the hooks and `lexicon://me` add a one-line note naming the path, never the contents.
- Project-scope writes (`init --project`, `add --project`, `import --project`, `learn --project`, `harvest --add`, `review --project`, and the MCP `add_term`, `learn_correction` and `harvest_repo {add: true}` tools) pin the file they wrote as trusted only when it did not exist yet or was already trusted. An existing untrusted or changed file makes the write fail with `ProjectTrustError` before anything is read, so a hostile repo file can never be laundered into trust. `recordHits` silently skips untrusted project files.
- Schema hardening: canonical/alias at most 80 characters, notes/phonetic 200, 64 aliases per term, 5000 terms, no control characters or line breaks; zero-width, bidi and BOM characters are stripped. Lexicon files over 2 MB and imports over 8 MB are refused. The `claude-md` export escapes `|` and line breaks in table cells. See SECURITY.md.

### Internal

- ESM, NodeNext, no default exports, no `any` in public signatures. Cross-module imports go through `src/core/index.js` only.
- `harvest.ts` exports `HARVEST_STOPLIST` (README-word filter), distinct from `matcher.ts` `STOPLIST` (prose guard), to avoid an `export *` collision.
- `src/mcp/server.ts` keeps an `EXPORT_FORMAT_VALUES` tuple with a compile-time exhaustiveness check against `ExportFormat`.
- `hookConfigFor` and `mergeHookIntoSettings` take an optional list of events; `HOOK_EVENTS` is `['UserPromptSubmit', 'SessionStart']`.
- The hook, CLI and daemon tests inject IO and clipboard functions; MCP and CLI tests mock `src/core/index.js`.
- `src/hooks/user-prompt-submit.ts` exports `dropCorrectionSpans(result, correction)` (pure; returns the same object when nothing overlaps). `parseCorrection` runs before `normalize` in the hook so the filter can apply.
- `docs/DOGFOOD.md` records the live run against Claude Code 2.1.257 that found both hook bugs.
