# Changelog

All notable changes to `@ashlr/lexicon` are recorded here. The format follows Keep a Changelog. Versions follow semver.

## 0.3.0 (2026-09-19)

### Added
- `lexicon setup`: the guided first run. Creates the global lexicon, seeds your name (from `git config user.name`) and your company or product name (suggested from the package scope or the git remote org) with suggested aliases and a phonetic hint, harvests the current repo into the project lexicon (top 10, min-count 5), detects which agent clients are on the machine (config dir, app bundle or CLI on PATH) and installs the MCP server and hooks into the ones you tick, installs the local API as a login service, exports for Wispr Flow, Superwhisper or macOS Text Replacement to `~/Desktop`, and ends with a summary card and three next actions. `--yes` takes every default, `--clients a,b|none`, `--company`, `--person`, `--phonetic`, `--app`, `--no-harvest`, `--no-serve`, `--reseed`, `--json` (machine-readable `SetupSummary`; `runSetup()` is exported for the MCP onboarding tool). Reruns never duplicate terms or hook entries.
- Install script: `curl -fsSL https://ashlrai.github.io/lexicon/install.sh | sh` (`scripts/install.sh`, copied into the demo site by `npm run build:site`). POSIX sh: checks Node 20+ with install hints, installs from npm when the package is on the registry, otherwise from GitHub at the latest tag (`LEXICON_REF` overrides), verifies `lexicon --version`, then runs `lexicon setup` on a terminal (`LEXICON_NO_SETUP=1` skips it).
- Homebrew: `brew install ashlrai/tap/lexicon` (`packaging/homebrew/lexicon.rb`, published to `ashlrai/homebrew-tap`; depends on `node`, recommends `ffmpeg` and `whisper.cpp` for `lexicon voice`).
- `docs/QUICKSTART.md`: the five-minute path from the one-liner to a corrected sentence in Claude Code.
- `package.json` gains a `prepare` script (`npm run build && npm run build:bundle`) so `npm install -g github:ashlrai/lexicon#v0.2.0` builds `dist/` and the plugin bundles on install. A plain `npm install` in the repo now runs the build too.
- Release assets: a `v*` tag now attaches `ashlr-lexicon-<version>.tgz` (npm pack), `lexicon-extension.zip`, `lexicon-extension-firefox.zip`, `LexiconBar.app.zip` (built on a macOS runner in a second `macos` job) and `SHA256SUMS` to the GitHub release. `npm publish` still runs only when `NPM_TOKEN` is set. See `docs/RELEASING.md` for the release steps, the token note and the Homebrew formula bump.
- README on-ramp: a "Try it in 60 seconds" block (install script, Homebrew, npm), a compact Install section that links `docs/QUICKSTART.md` and the release downloads, and an "Agent-native" note on the setup, doctor, install, trust, import and suggest MCP tools and the `onboard` prompt.
- Demo site: an Install section with copyable install commands and download buttons for the extension zips and `LexiconBar.app.zip` from the latest release.
- Agent-native setup: the MCP server grows seven tools so an agent can onboard, install, trust, import, diagnose and improve the lexicon without the user opening a terminal (`docs/AGENT-NATIVE.md`). `lexicon_doctor {}` returns the doctor checks as `{ ok, checks: [{ level, message }], paths, versions }`; `install_client { client, apply?, scope? }` previews (default) or applies the MCP registration for claude, codex, cursor, windsurf, gemini, vscode or claude-desktop; `trust_project { action: 'status'|'trust'|'untrust', path? }` reports trust with a sanitized preview (canonicals, first alias, counts) so the model shows the user what it is trusting; `import_dictionary { path? | content?, format?, scope?, dryRun? }` reuses the CLI importers (8 MB cap); `suggest_terms { cwd?, limit? }` returns `TermSuggestion[]` and `apply_suggestion { suggestion, scope? }` applies one (alias merge, new term, never-word, stale removal); `setup_lexicon { company?, person?, clients?, serve? }` runs `lexicon setup` non-interactively and returns its summary; `serve_status {}` checks the local API's `/health`. A new `onboard` prompt scripts the first-run conversation (names with exact spelling and pronunciation, teammates, clients, `setup_lexicon`, `add_term`, one test sentence). `SERVER_INSTRUCTIONS` now mention onboarding, doctor, suggestions, preview-before-apply and trust-after-preview.
- The SessionStart hook, when the merged lexicon has no terms, emits at most once per 24 hours (`<config dir>/onboard-note.json`) a note asking the model to offer setup via `setup_lexicon` or the `onboard` prompt. Never emitted when terms exist.
- `runDoctorReport(opts, deps?): Promise<DoctorReport>` and `renderDoctorReport(report, io)` in `src/cli/commands.ts`; `runDoctor` renders from the report and its output is unchanged.
- `lexicon suggest`: what the lexicon should learn next, mined from `voice/history.jsonl` and the lexicon itself (`suggestTerms()` in `src/core/suggestTerms.ts`, also behind the `suggest_terms` MCP tool). Four kinds: `alias` (a recurring garble left uncorrected next to a term it sounds like, a phonetic/fuzzy guess the matcher keeps making, or a rewrite the older rules made that the current ones no longer reproduce), `term` (a capitalized name recurring in corrected output that is not in the lexicon, with `suggestAliases`; plus the top repo harvest candidates with `--harvest [dir]` or an explicit `--cwd`), `never` (an ordinary word an older or current guess rewrote to a term), `stale` (30+ days old, no hits, never dictated). Ranked by `confidence * log(1 + count)`, evidence sanitized and capped at 120 characters, under 100 ms for 1000 lines and 200 terms. `--json`; `--apply` walks them (y/n/a/q; removing a stale term is never the default); `--yes` applies everything at or above 0.80 confidence (harvest candidates and stale removals never qualify); `--limit`; `--project` for new terms. See `docs/SUGGEST.md`.
- SKILL.md gains a "Setup and maintenance" section; `/lexicon` gains `setup`, `doctor`, `suggest` and `trust [path]`.

### Changed
- Roadmap: dropped the finished items (browser extension, macOS app, real-audio benchmark) and the stale "No Chrome extension" non-goal; kept store listings, notarization, a Windows/Linux tray app, non-English phonetics and a real-microphone benchmark.

## 0.2.0 (2026-09-19)

Desktop coverage: surfaces without hooks or MCP.

### Added
- Browser chats: a Manifest V3 extension (`extension/`, `npm run build:extension`) that fixes brand and product names in the ChatGPT, Claude, Grok, Gemini, Perplexity, Poe and Copilot composers before the message is sent, via the local `lexicon serve` API or an embedded copy of the lexicon. See `docs/EXTENSION.md`.
- LexiconBar, a native macOS menu bar app (`apps/macos/LexiconBar`, SwiftPM, no dependencies) that fronts the CLI: push to talk (⌃⌥Space, toggle) via `lexicon voice --toggle --json`, "Fix clipboard now" (⌃⌥V) via `lexicon daemon --once`, checkboxes that supervise `lexicon daemon` and `lexicon serve` as child processes (5 s backoff, 5 restarts), a "Last correction" submenu, Open lexicon file / Stats / Run doctor, Start at login, notifications after each run, and Preferences (CLI path with auto-detect, whisper model, paste vs copy, hotkey recorder). `scripts/build-macos-app.sh` builds and ad-hoc signs `apps/macos/build/LexiconBar.app`; the `macos-app` workflow uploads the zip. See `docs/MACOS-APP.md`.
- `lexicon voice`: local push-to-talk dictation, ffmpeg (16 kHz mono WAV) -> whisper.cpp with the lexicon canonicals as `--prompt` -> `normalize()`. Prints the corrected text, `--copy` puts it on the clipboard, `--paste` pastes into the frontmost app (macOS; elsewhere falls back to copy with a notice), `--json` prints `{ raw, output, replacements, summary, model, seconds, ms }`. `--toggle` is the hotkey mode (first press starts a detached recording and writes `voice/recording.json`, second press stops, transcribes and outputs; stale state is cleaned up; `--status` reports `recording since <time>` or `idle`). `--model <name|path>` (default `base.en`, auto-downloaded from Hugging Face into `<config dir>/models`, `LEXICON_WHISPER_MODELS` overrides, the repo's `bench/audio/models` is a fallback), `--device` and `--list-devices` (avfoundation, pulse/alsa, dshow), `--seconds`, `--lang`, `--translate`, `--no-prompt`, `--no-history`. Every transcription appends to `voice/history.jsonl` (capped at 1000 lines) and records hits. Exit 2 with install hints when ffmpeg or whisper-cli is missing (`LEXICON_WHISPER_BIN` / `LEXICON_FFMPEG_BIN` override), exit 3 when nothing was heard. `lexicon doctor` reports whisper-cli, ffmpeg, the default model and the macOS Microphone permission note. See `docs/VOICE.md`.
- `lexicon serve`: a local HTTP API on `http://127.0.0.1:41733` (`node:http`, no framework) for surfaces without hooks or MCP: the browser extension, Claude Desktop, the Codex app, macOS Shortcuts, Raycast and the menu bar app. Endpoints `GET /health`, `POST /normalize`, `POST /learn`, `POST /add`, `GET /lexicon`, `GET /export/:format`, `GET /stats`; bearer token in `<config dir>/serve.json` (mode 0600, created on first run); CORS only for browser-extension origins or `serve.json.allowedOrigins`; 1 MB body cap, 64 concurrent requests, lexicon reloaded at most every 2 s and after every write, trust gate unchanged. `--show` prints the URL and token, `--status` checks `/health`, `--install`/`--uninstall` manage a launchd LaunchAgent (macOS) or systemd user unit (Linux) and print Scheduled Task instructions on Windows. `createServer()` from `src/serve/server.ts` is embeddable. See `docs/LOCAL-API.md`.

### Changed
- Matcher: an ordinary word is no longer rewritten to an alias-less sound-alike term (`lacks` became `Locus` at `phonetic 0.90` in production; both key to `LKS`, and the 0.88 bar only covers terms with aliases). The built-in stoplist moved to `src/core/stoplist.ts` (re-exported from `matcher.ts`) and grew from about 600 to 3376 words in their usual inflections; it still blocks only the phonetic/fuzzy passes and implicit aliases, so explicit aliases win, and product names that double as words (`docker`, `neon`, `whisper`) stay off it. A single-token phonetic candidate must now also resemble the alias in spelling, more so the shorter its metaphone key: similarity 0.8 on a 3-consonant key, 0.65 on 4, none on 5 or more (`coopernetties` -> Kubernetes still matches). Benchmark unchanged on positives (99.6% excl. hard / 96.5% recall); prose false positives incl. expected-hard 14.2% -> 12.5% (`graphical` -> GraphQL and `tropic` -> tRPC no longer fire). A bare `entire` no longer becomes `Entire.io`; list `entire` as an alias to opt in.
- Matcher: a name glued to an identifier is left alone in every pass, the exact alias pass included (`@ashlr/lexicon` became `@Ashlr.AI/lexicon` in production through the implicit stem alias of `Ashlr.AI`). A window directly preceded by `@ / # : \ ~ _ -` or directly followed by `/ \ _` is skipped (`@ashlr/lexicon`, `ashlrai/lexicon`, `ashlr_core`, `#ashlr`, `~/ashlr`, `C:\ashlr`), whether or not `skipCode` is on; only the characters outside the window count, so a listed `ashler-ai` alias still matches, and a possessive (`ashler's`), sentence punctuation (`ashler,` / `ashler.`) and a spaced hyphen (`ashler - it works`) are rewritten as before. Path skipping now also covers a whitespace-free `scope/name` slug without a file extension (`ashlrai/lexicon`, `github.com/ashlrai/lexicon`). Benchmark unchanged on every headline number (99.6% / 96.5% recall, 12.5% prose FP incl. hard, 0.0% excl. hard).
- Matcher: identifiers glued to `@`, `/`, `#`, `_` or `-` (package scopes, repo slugs, paths) are never rewritten.

## 0.1.0 (2026-09-19)

Initial release.

### Added
- `lexicon review` re-reads the file before its final write and merges hits, aliases and terms changed elsewhere while it ran.
- The UserPromptSubmit hook and the clipboard daemon (loop and `--once`) record `hits` best-effort in the background, so `lexicon stats` counts hook-only and clipboard usage.
- Core exports `stripControlChars`, `sanitizeForDisplay`, `DISPLAY_MAX_CHARS`.
- `parseCorrection` stops the heard side at a sentence boundary: "it's Ashlr.AI not Ashlur. remember that." yields `heard: "Ashlur"` and a following sentence ("... not Ashler. Now deploy it to Vercel.") is ignored. A period stays inside a bare word only when something follows it directly (`Ashlr.AI`, `Entire.io`, `README.md`).
- The UserPromptSubmit hook no longer normalizes the words being corrected: on a correction prompt it drops any replacement overlapping `heard` or `meant`, rebuilds the corrected prompt from the rest, records no hit for the dropped terms, and emits only the correction note when nothing else changed. The note names its fields (`heard: "Ashlur", meant: "Ashlr.AI"`), tells the model to pass only the name when the capture carries trailing words, and ends with "Then continue with the rest of the message."
- README: manual installs do not load `SKILL.md`; a "Headless and scripted use" note (`claude -p`, `--allowedTools mcp__lexicon`, `LEXICON_PATH` reaching hook and server); `lexicon stats` counts hook matches from any session. SKILL.md: trailing-word guidance for the hook's `heard`, and the one-time ToolSearch turn in sessions with many MCP servers.

- Lexicon file format (`version: 1`): terms with `canonical`, `aliases`, `phonetic`, `category`, `notes`, `never`, `caseSensitive`, plus tool-managed `source`, `createdAt`, `hits`; settings `minConfidence`, `phonetic`, `fuzzy`, `protectedWords`, `skipCode`.
- Global file at `~/.config/lexicon/lexicon.yaml` (override with `LEXICON_PATH` or `XDG_CONFIG_HOME`) and project `.lexicon.yaml` at the git root. Project wins on collision, aliases unioned.
- Matcher with three tiers: exact alias, phonetic (double metaphone), fuzzy (Damerau-Levenshtein). Built-in stoplist of about 300 common English words, `protectedWords`, per-term `never`, code span and URL skipping, three-character minimum for guessed matches. Explicit aliases always beat the stoplist.
- Matcher precision (benchmark in `docs/BENCHMARK.md`, prose false positives 18.9% -> 0.0% excluding expected-hard, positive sentence accuracy 88.1% -> 94.2%): exact hits win overlap resolution; inexact windows never start or end on a function word; possessives survive phonetic and fuzzy matches; spans already equal to a canonical are claimed; no phonetic match on keys under 3 characters, windows under 4 letters or spelled-out aliases; lone lowercase words against aliased terms need 0.88; diacritics folded in the exact pass; transposition-aware similarity.
- Matcher: a capitalised sound-alike is no longer rewritten to an aliased term on a weak phonetic hit (`Inter`, the font, became `Entire.io` at 0.86 in production). The 0.88 aliased-term bar now applies to every single-token phonetic candidate regardless of case, and a lone candidate that keys alike only because double metaphone folded its initial vowel (`inter` / `entire`, `email` / `yaml`) must share its first letter or reach similarity 0.6. Benchmark unchanged on positives (94.2% / 96.5% recall); prose false positives incl. expected-hard 15.0% -> 14.2%.
- `normalize` with replacement offsets, reasons, confidence and a one-line-per-change diff summary. Dry-run mode.
- Alias suggestion (`suggestAliases`) that generates likely STT misspellings of a canonical.
- Correction learning: `parseCorrection` recognises "it's X not Y", "I said X not Y", "I meant X not Y", "not Y, X", "replace Y with X", "Y -> X", "Y should be X", "spelled X" and quoted forms; `learnCorrection` adds the heard form as an alias of the matching term or creates a `source: learned` term; `suggestCanonicalFor` returns the closest existing terms for "did you mean".
- Usage stats (`computeStats`): term and alias counts, total hits, top ten terms, never-hit terms, per-category, per-source and per-file breakdowns.
- Repo harvester: package and module names, PascalCase identifiers, git authors, directory name, README proper nouns. Bounded scan (5000 files, 512 KB per file), ignores build and dependency directories.
- Exporters (15): `wispr`, `superwhisper`, `whisper-prompt`, `macos`, `claude-md`, `csv`, `json`, `deepgram`, `espanso`, `assemblyai`, `azure`, `google`, `openai`, `text`, `markdown`.
- Importers (7, plus `auto` content detection): `wispr`, `superwhisper`, `macos`, `espanso`, `text`, `csv`, `json`. Rows merged by canonical; `text`, `csv`, `macos` and `json` round-trip with their exporters. Inputs over 8 MB are refused.
- MCP stdio server `lexicon-mcp` with tools `normalize_transcript`, `add_term`, `remove_term`, `list_terms`, `harvest_repo`, `export_lexicon`, `learn_correction`, `suggest_canonical`, `lexicon_stats`; resources `lexicon://me` and `lexicon://json`; prompt `voice-context`; server `instructions` sent at connect. `normalize_transcript` bumps each matched term's `hits`. `list_terms` and `lexicon://me` report a skipped untrusted project file by path only.
- Claude Code hook (`plugin/hook.mjs`, `lexicon hook`), dispatched on `hook_event_name`. `UserPromptSubmit` injects the diff and corrected prompt as `additionalContext`, prints nothing when unchanged, always exits 0, about 100ms measured; when the prompt is a spelling correction it adds a line asking the model to call `learn_correction` (the hook never writes). `SessionStart` (startup, resume, clear, compact) emits the `claude-md` export of the merged lexicon, capped at about 4000 characters with a "... N more terms; read the lexicon://me resource" line; an empty lexicon emits nothing.
- Self-contained Claude Code plugin: `plugin/mcp-server.mjs` and `plugin/hook.mjs` are committed esbuild bundles (every dependency inlined, Node 20+, unminified) that `.mcp.json` and `hooks/hooks.json` point at, so `claude plugin install lexicon@ashlrai` works from a bare clone with no `npm install` or build. `npm run build:bundle` regenerates them; `npm run check:bundle` (run in CI) fails when they are stale; `prepublishOnly` builds them. `plugin/` ships in the npm package; `dist/` stays untracked. The MCP server reads its version from whichever `package.json` (one or two levels up) is `@ashlr/lexicon`.
- Claude Code plugin packaging: `.claude-plugin/plugin.json`, `.mcp.json`, `hooks/hooks.json`, a `lexicon` skill and a `/lexicon` command (`add`, `learn`, `stats`, `harvest`, `export`, `remove`). Marketplace manifest (`.claude-plugin/marketplace.json`): `claude plugin marketplace add ashlrai/lexicon` then `claude plugin install lexicon@ashlrai`.
- CLI `lexicon` (21 commands, global `--cwd`): `init --project`; `add` (`--phonetic --category --notes --never --project --suggest -i`); `remove --project`; `list` (`--json --category --query`); `normalize` (`--json --diff --dry-run --min-confidence --no-phonetic --no-fuzzy --include-untrusted`, always exits 0 and passes text through on error); `harvest` (`--limit --min-count --add --yes -i --json`); `export` (`--out --category --limit`); `import <file> [format]` (`--format --project --dry-run --source --category --json`); `learn` (`--from --project --json`); `stats --json`; `review` (`--never-hit --project --global --category`); `edit --project`; `trust [path]` (`--list`); `untrust [path]`; `path`; `doctor`; `mcp`; `hook`; `daemon` (`--once --paste --interval --dry-run --quiet --backend --which`); `install-claude` (`--apply --scope`); `install [client]` (`--apply --scope --project --home`).
- Interactive CLI workflows, dependency-free (`src/cli/prompt.ts` over `node:readline`) and refusing to run without a TTY: `harvest --add` on a terminal walks candidates with `y`/`n`/`e` (edit aliases)/`c` (category)/`a` (add all)/`q` (`--yes` opts out, `--interactive` forces it); `add -i` turns the suggested aliases into a checklist and asks for the phonetic hint and category; `review` walks existing terms with `k`/`d`/`e`/`p`/`n`/`q` and writes once at the end; `edit` opens the file in `$VISUAL`/`$EDITOR` and validates it afterwards without ever rewriting it.

Idempotent, keeps unrelated keys, ends with the `lexicon export claude-md` hint for that client's rules file.

### Security
- CLI output is sanitized against terminal escape injection: paths, canonicals, aliases, notes, harvest evidence and quoted error text pass through the new `sanitizeForDisplay`; `renderTable` sanitizes every cell. `normalize` stdout is unchanged.

- Project `.lexicon.yaml` files are skipped until approved with `lexicon trust` (preview, sha256 pinned in `<config dir>/trust.json`; `lexicon trust --list`, `lexicon untrust`). A changed file drops back to untrusted until re-trusted. `LEXICON_TRUST_ALL=1` bypasses the gate for CI. `loadLexicon()` takes `includeUntrusted` and reports `projectTrust` / `skippedProject`; `list`, `normalize` (`--include-untrusted`) and `doctor` warn; the hooks and `lexicon://me` add a one-line note naming the path, never the contents.
- Project-scope writes (`init --project`, `add --project`, `import --project`, `learn --project`, `harvest --add`, `review --project`, and the MCP `add_term`, `learn_correction` and `harvest_repo {add: true}` tools) pin the file they wrote as trusted only when it did not exist yet or was already trusted. An existing untrusted or changed file makes the write fail with `ProjectTrustError` before anything is read, so a hostile repo file can never be laundered into trust. `recordHits` silently skips untrusted project files.
- Schema hardening: canonical/alias at most 80 characters, notes/phonetic 200, 64 aliases per term, 5000 terms, no control characters or line breaks; zero-width, bidi and BOM characters are stripped. Lexicon files over 2 MB and imports over 8 MB are refused. The `claude-md` export escapes `|` and line breaks in table cells. See SECURITY.md.

### Internal

- ESM, NodeNext, no default exports, no `any` in public signatures. Cross-module imports go through `src/core/index.js` only.
- `harvest.ts` exports `HARVEST_STOPLIST` (README-word filter), distinct from `matcher.ts` `STOPLIST` (prose guard), to avoid an `export *` collision.
- `src/mcp/server.ts` keeps an `EXPORT_FORMAT_VALUES` tuple with a compile-time exhaustiveness check against `ExportFormat`.
- `hookConfigFor` and `mergeHookIntoSettings` take an optional list of events; `HOOK_EVENTS` is `['UserPromptSubmit', 'SessionStart']`.
- The hook, CLI and daemon tests inject IO and clipboard functions; MCP and CLI tests mock `src/core/index.js`.
- `src/hooks/user-prompt-submit.ts` exports `dropCorrectionSpans(result, correction)` (pure; returns the same object when nothing overlaps). `parseCorrection` runs before `normalize` in the hook so the filter can apply.
- `docs/DOGFOOD.md` records the live run against Claude Code 2.1.257 that found both hook bugs.
