# Changelog

All notable changes to `@ashlr/lexicon` are recorded here. The format follows Keep a Changelog. Versions follow semver.

## Unreleased

### Security

- Credentials no longer reach error text from an upstream.
  - The browser extension's popup errors quoted the server's `{ error }` text, so a server at the configured base URL that quoted the bearer token back showed the token. That text is now redacted.
  - `lexicon serve --status` and the MCP `serve_status` tool showed a failing `/health` reply's `error` as is, with the same risk for the `serve.json` token. That text is now redacted too.
  - Registry index and pack fetch errors named the full URL, including a query token or a password (fetch's own message quotes a URL with credentials). Those errors now name the URL without credentials, query or fragment.
  - Any run of 8 or more characters of the token is replaced with `[redacted]`.
  - A new test (`tests/upstream-redaction.test.ts`) drives each path against replies that quote the request, non-2xx statuses, a closed port and malformed URLs, and fails on any 8-character run of a canary.

### Documentation

- docs/EXTENSION.md: the Firefox notes now say to allow `127.0.0.1` and `localhost` in the add-on's permissions panel as well as the chat sites; pairing, Test connection and Sync need them.
- `docs/PHANTOM-USAGE.md`: using Lexicon with Phantom. Lexicon makes no model calls and has no gateway or base URL setting; `phantom exec` around an agent is unaffected; the `serve.json` token is local and not a Phantom secret.

### Added

- `GET /export/:format?json=1` answers `{ format, content, rows?, dropped?, note? }`, so a client of the local API can read what a format left out: the `X-Lexicon-Note` header is ASCII and could only say that entries were left out, not which. `dropped` holds the same sentences as `lexicon export --json`, and the header now names `?json=1` too.
- `lexicon uninstall <client>` takes back out what `lexicon install <client> --apply` wrote, for every install client, with the same `--scope`, `--project` and `--home`. Only entries an install writes are removed: a `lexicon` server launched as `node <dir>/plugin/mcp-server.mjs`, `node <dir>/dist/mcp/server.js` or `npx -y @ashlr/lexicon mcp`, Codex's `[mcp_servers.lexicon]` table with its sub-tables, and for `claude` the registration (checked with `claude mcp get`, then `claude mcp remove`) and the hook commands `install claude` writes. A server of your own named `lexicon` is named and left alone, and a JSON or JSONC config keeps every other byte, comments included. `--dry-run` prints what would go and writes nothing; `--json` prints `{ ok, client, scope, dryRun, changes, output }`.
- Corrections the UserPromptSubmit hook notices ("it's Vercel not versel") are queued for review in `pending-aliases.yaml`, next to the global lexicon (mode 0600, at most 200 entries, repeats counted). The queue is never applied on its own: the matcher does not read it, so matching is unchanged until you accept. `lexicon pending` lists the queue (`--json`), `lexicon pending accept <id...>` (or `--all`) learns each entry through the same path as `lexicon learn` and removes it, and `lexicon pending reject <id...>` drops entries without learning them. Corrections the lexicon already knows are not queued, a pending file that cannot be read is left alone rather than overwritten, and a queue failure never changes the hook's output. `LEXICON_QUEUE_CORRECTIONS=0` turns queueing off. The hook's `learn_correction` note to the agent is unchanged.
- MCP `uninstall_client { client, apply?, scope? }`, the agent-facing counterpart of `lexicon uninstall <client>`. It is a dry run unless `apply: true` (a safety default for a tool that removes config), returns `changes` as `lexicon uninstall --json` does, removes only what an install wrote, and answers a project scope for windsurf or claude-desktop by saying to call again without scope. The server now has twenty-one tools.

### Fixed

- `lexicon serve`'s per-directory lexicon cache drops the least recently used directory once it holds 32, not the first one loaded, so the directory a client asks for most is no longer reloaded each time 32 others have been asked for once.
- `lexicon serve` gives a request 30 seconds to arrive (its headers 10), then answers 408 with `{ error }` and closes it. Node's default was 300 s, so a client that sent its headers and trickled the body, or never sent it, held one of the 64 request slots for five minutes.
- `lexicon serve`'s plain `/health`, asked without the token (the browser extension's status check does this), says when a lexicon file does not parse and names `lexicon serve --status` and `lexicon doctor` for the file and line. It said only `internal error (the lexicon serve log has the detail)`, so the popup gave no hint that the fix was an edit to the lexicon. The path is still left out without the token.
- `lexicon serve` answers a request it cannot parse (a malformed request line, headers over Node's limit) with its usual `{ error }` JSON body and the status Node would give (400, 431 or 408). Node's own answer was a status line with no body, the one error of the API a client could not read as `{ error }`.
- `lexicon serve` no longer invites a body it will refuse. Node answered every `Expect: 100-continue` with 100 Continue, so a client announcing a body over the 1 MB limit (curl does this for large uploads) sent all of it, and past 16 MB the connection was cut, so the client saw a reset instead of the 413. Such a request now gets the 413 at once, before the body is sent.
- A real name that speech-to-text wrote by sound is a correction again when said in a sentence: "it's Siobhan not Shivon" was refused as a change of meaning because the two spellings neither look nor share a phonetic key. Two one-word names (not all capitals, the heard one not an everyday word) now also count when their sounds match loosely (b, f and v alike, sh and s alike), and, when the lexicon already holds the meant spelling, when they are close ("it's Niamh not Neve" with Niamh a term). The prompt hook and `lexicon learn` pass the lexicon. "it's the API not the UI", "it's Monday not Tuesday" and "it's Postgres not MySQL" are still refused.
- `lexicon learn --from "spelled Zoë"` on Windows printed `lexicon learn <heard> & 'Zoë'`: the spelling was quoted as a whole PowerShell command, call operator included. It now prints `lexicon learn <heard> 'Zoë'`.
- Two `lexicon voice` runs downloading the same model at once on Windows could fail the second, finished download with EPERM while the first was renaming its file into place. The rename into place is now retried for about a second on EPERM, EACCES and EBUSY.
- `lexicon daemon` on Windows no longer reports a working clipboard as hung. Each read and write starts a new `powershell.exe`, and a cold start on a busy machine took over the 5 s limit, so the clipboard was left uncorrected; the PowerShell backend now allows 20 s. The other backends keep 5 s.
- Browser extension:
  - A site reached through "Any site" can be paused from Options: the site list showed only the built-in chat sites and hosts already switched in the popup. The background now remembers the host name of each tab it checks text for through "Any site" (at most 100, no paths or text), and Options lists them with their switch.
  - A very long composer no longer costs a full walk of its text several times per check. A composer over 1 MB, the local API's request limit, is not checked at all (a toast says so and the send goes on as typed), where each keystroke sent the whole text to the background; a check now reads the text, code ranges and caret in one pass instead of three, and a correction walks the composer twice instead of four or five times.
  - On a built-in site whose send button selector no longer matches and which ignores a replayed Enter, pressing Enter on text with a correction did nothing: the press was held for the check and the replay never sent. Without a button to click, Enter is now held only once the page is seen to take an Enter, and otherwise goes on as typed; a check that still cannot send says so in the toast ("Not sent: ... Press Enter again to send.").
  - In a composer inside an open shadow root the caret is read and put back in the right place: the content script asked `document.getSelection()`, which there points at the shadow host, so the caret read as the end of the text (live mode then checked the whole box and moved the caret to its end) and a caret inside inline code there was missed. It now uses the shadow root's own selection where the browser has one.
  - A correction in a textarea or text input can be undone with Ctrl+Z (Cmd+Z): it was written by assigning the field's value, which drops the browser's undo history. It is now the browser's own edit (`insertText` while the field has focus, else `setRangeText`), with the value assignment kept only as the fallback.
  - Whether the extension is on for a page is checked again when a single-page app changes its URL, not only at load and on a settings change: moving from Grok on X (`x.com/i/grok`) to another x.com page in the same tab left corrections running there until a reload.
  - A composer inside an iframe is corrected: the content script ran in the top frame only. It now also runs in a frame that is part of the page (same origin, including an `about:blank` editor frame) and in a chat site embedded in another page, under the tab's site switch; a frame from another origin (an ad, a payment field) is still left alone.
  - A text box inside a web component (an open shadow root) is corrected on Enter and prechecked as you type. The content script read the shadow host, which is not editable, as the event target and the focused element, so such a composer was skipped on "any site".
  - Live mode no longer rewrites the composer during an IME composition (Japanese, Chinese or Korean input, some dictation), which cancelled or garbled the word being composed; it checks once the composition ends.
  - Turning "Any site" off now stops corrections in tabs that are already open on other sites, not only after a reload, and the popup no longer says "Corrections run before each send." on a site the extension does not cover; it points at the "Any site" option instead.
- The macOS clipboard watcher (`lexicon daemon`) keeps non-ASCII text intact when it runs with no locale set (under launchd, cron or `env -i`): pbpaste and pbcopy now get a UTF-8 `LANG` and `LC_CTYPE` when the environment names none, instead of reading and writing `Zoë` or `東京` in a legacy encoding. A locale you set is left alone.
- `lexicon harvest --interactive` with nothing to walk no longer says only "no candidates to review", and plain `lexicon harvest` no longer only "no candidates found": both say why (names seen fewer than `--min-count` times or only as code symbols, with the flag that includes them; a directory with nothing to read; files scanned with no name in them) and what to try. A walk whose candidates are all already terms with their aliases says so instead of asking about each.
- `lexicon harvest` and MCP `harvest_repo` say when the scan stopped at its 5000-file cap, so a large monorepo no longer looks fully scanned: a `warn:` line (stderr under `--json`), and `truncated: true` with a `note` in `--full` and the MCP answer, naming a subdirectory harvest as the way to scan the rest.
- Harvesting a subdirectory of a repo, or a directory in it git does not track, no longer proposes every author of the enclosing repo: below the top of a work tree only the authors of commits that touch the harvested directory are read.
- "it's Ashlr not ashlr.ai", where Ashlr is an alias of the term Ashlr.AI, no longer says "Ashlr.AI is already the canonical spelling" as if the correction were in place. The lexicon corrects Ashlr to Ashlr.AI, the other way round, and `lexicon learn`, serve `POST /learn` and MCP `learn_correction` now say so, with how to make Ashlr the canonical if that is what you want (`lexicon edit` and rename the term, or the `remove_term` and `add_term` calls). The answer carries the additive `reversed: true`.
- "it's the API not the UI" is no longer a spelling correction: `lexicon learn --from` learned "the UI" as an alias of "the API" (so every later "the UI" was rewritten), and the UserPromptSubmit hook asked the agent to learn it. Two unquoted sides must now look or sound alike (edit distance or the phonetic key, after the words both share are set aside); real speech-to-text corrections such as "Cooper Netties" for Kubernetes, "engine x" for nginx, "kates" for k8s and "actually i" for Ashlr.AI are still learned. `lexicon learn` says why such a sentence learned nothing and names the two-word `lexicon learn <heard> <meant>` command for when it really is what speech-to-text writes; quoting a side still marks it as a spelling.
- `lexicon trust --list`, the pack registry index, `lexicon pack search` and the `lexicon stats` category and source lines no longer sort by your locale: under `LC_ALL=lt_LT.UTF-8` `acme/yak` came before `acme/jam`, and under `sv_SE` a path with `Ä` came after one with `Z`. They use the same fixed collation as the learning pipeline (`compareText`).
- Commands printed for you to run are quoted for your shell everywhere, through the same `shownCommand`/`commandLine` quoting as `install` and `setup`: the learn/add conflict notes (CLI `--json`, serve `POST /learn`, the extension popup), the `lexicon remove` "still in the other lexicon" line and its global-copy hints and `nextStep`, and setup's "add one now" line. They were JSON string literals, so a `$` in a name expanded in the shell and a `'` or `"` could break the argument. In the extension the commands are quoted for a POSIX shell.
- `lexicon suggest --harvest` with nothing to suggest no longer tells you to run `lexicon suggest --harvest`; it says the voice history and the scanned directory hold nothing new.
- The commands `lexicon learn` prints (`run: lexicon learn <heard> ...`, and the `lexicon remove ... --alias ...` that drops a conflicting alias, which `lexicon add` prints too) are quoted for your shell like every other printed command. They used JSON quoting, which left a `$` or a backtick in a spelling for a POSIX shell to expand and is not how PowerShell quotes; a plain word such as `Ashlr.AI` is now written bare.
- `lexicon harvest` (and setup's harvest step and `lexicon suggest --harvest`) honors `.gitignore`. It skipped only a fixed list of directories, so a repo's ignored build output (`out/`, a generated client) was scanned and its names proposed. In a git work tree it now reads the files `git ls-files --cached --others --exclude-standard` lists; outside one it walks the directory as before.
- `suggest_canonical` (and `suggestCanonicalFor`) compares spellings in NFC: a name with a decomposed accent, as pasted from a macOS file name, scored 0.9 against the canonical it spells exactly instead of 1.
- `lexicon stats`, `suggest_canonical`, `lexicon harvest` and `lexicon suggest` broke ties in the user's locale, so under `LC_ALL=sv_SE.UTF-8` `Äpple` came after `Zeta` and the same lexicon listed in another order (a harvest that reached its 5000 file cap even scanned other files). They now use the fixed order the exports use.
- The spellings `lexicon add`, `lexicon learn`, setup and `GET /aliases` guess for a new name no longer include a single everyday word, which was then rewritten wherever it was said: `Entire.io` got the alias `Entire` and `Flyy` got `Fly`, so "birds fly over the entire field" came out as "birds Flyy over the Entire.io field". An acronym's pronounced form (`SaaS` -> `sass`) is kept, since that is what speech-to-text writes for it.
- A number corrected in passing ("it's 2024 not 2023") is no longer read as a spelling correction. The prompt hook flagged it for `learn_correction` and queued it in `lexicon pending`, and once learned it rewrote every 2023 in a transcript to 2024. A correction whose intended spelling has no letter is now ignored by `parseCorrection` (the hook, `lexicon learn --from`); `lexicon learn 2023 2024` with two words still learns it.
- Learning a correction the lexicon already knows writes nothing. `lexicon learn`, MCP `learn_correction`, `POST /learn` and `lexicon pending accept` rewrote the lexicon file with the same bytes (a watcher saw a change, a project file's timestamp moved), and with `--project` (or `scope: "project"`) for a global term they wrote a copy of the term with no aliases into the project file and reported it created. Now the result says nothing was added, and a scope the term does not live in gets the term with `heard` as its alias. A case-only correction whose spelling is the canonical in another Unicode form (`Zoe` plus a combining diaeresis) no longer rewrites the term and reports it changed.
- `lexicon setup | tee log` (a terminal on stdin, a pipe on stdout) took every default under a `(no terminal ...)` line that went into the pipe. It now says on stderr that stdout is not a terminal, so no questions were asked and the defaults were taken, and how to answer them: run it without the pipe, or pass `--app`, `--clients`, `--packs`, `--serve` or `--harvest`. Prompts stay off then, since the lines they refer to go to stdout.
- Running `lexicon setup` again no longer writes over a dictation export you edited. When `~/Desktop/lexicon-<app>.<ext>` (or the `--export-dir` file) differs from the new export, a terminal asks whether to replace it (default no); without a terminal, or on a no, the file is kept, setup says so, and the export goes to the next free `lexicon-<app>-2.<ext>` (reused when it already holds the same export). A file that already holds this export is rewritten as before. `--dry-run` names the file it would write.
- On Wayland the clipboard watcher writes with `wl-copy --type text/plain`. Without a type wl-copy guesses one from the bytes, so a correction that looked like markup or a path could be offered as something a text field does not paste. The other backends already write plain text.
- `lexicon daemon --once --paste` no longer pastes a clipboard it left as it was (too large, binary such as a copied image, or with no letters): the shortcut is meant to paste dictated text, so it pasted something else. It says why on stderr: `--paste skipped: clipboard too large, so it was left as it was and nothing was pasted`.
- A second ctrl-C stops `lexicon daemon` at once. The first one waits for a clipboard read in flight (a clipboard tool that hangs runs until its timeout) and now says so; before, its listener was gone and the daemon did not answer a second one.
- The clipboard watcher (`lexicon daemon`) saw a lexicon edit up to 5 seconds late, so a term just learned was not used on the next copy. Before it corrects a new clipboard text it now checks (with `stat`) whether the global or project lexicon or `trust.json` changed, and reloads if so; the 5 second reload stays as a backstop.
- The spreadsheet formula guard of `lexicon export csv` and `lexicon export wispr` checked only a cell's first character, so a name such as ` =HYPERLINK(...)`, which a spreadsheet trims and then runs, was written as is. Spaces or tabs ahead of `=`, `+`, `-` or `@` now count: `csv` writes the cell with a leading `'`, `wispr` leaves the pair out and names it.
- `lexicon export wispr` and `lexicon export superwhisper` write an alias two terms share once, for the more used term (ties go to brand, person and product, then A to Z), as `espanso` and `macos` already did; the term left out is named in the export's notes (stderr, `dropped` under `--json`). Before, both rows were written and the app replaced the word with either name.
- A command a preview or refusal tells you to run is printed whole. `to write step 1, run: ...`, `to perform steps 1 and 2, run: ...` (`lexicon install`), `to apply, run: ...` (`lexicon setup --dry-run`), `to remove it, run: ...` (`lexicon uninstall --dry-run`) and the `pack add` / `pack update` `--yes` command were capped at 200 characters like any displayed text, so a deep temp or home directory (macOS puts temp files under `/var/folders/...`) ended them in `…` and printed a command that could not be run. They are still stripped of control characters.
- On Windows every printed command is quoted for PowerShell, the way the `lexicon voice` whisper rerun already was. The install, setup, uninstall and pack commands used POSIX quoting there, which single-quoted every backslash path and wrote a `'` in a name as `'\''`, which PowerShell does not read back as the same word; the `claude mcp add` line double-quoted paths, so a `$` in a directory name was read as a variable. Now a backslash path is bare, a quoted word is single-quoted with `'` doubled, and a comma list such as `--clients claude,cursor` is quoted, since PowerShell otherwise passes it as two arguments.
- `lexicon daemon` stops a clipboard tool that runs for more than 5 seconds (`xclip -o` waiting on an app that holds the clipboard and does not answer) and reports it once, then keeps polling. The read never settled, so the watcher silently stopped correcting and the stuck tool kept the process alive after ctrl-C.
- `lexicon daemon` on Windows leaves a clipboard with both CRLF and LF line breaks as it is. It was read as all LF and written back as all CRLF, changing lines no correction touched.
- `lexicon setup`'s dictation export says what the format left out (a pair a spreadsheet would run as a formula, a shortcut two terms share) on stderr, as `lexicon export` does, and counts the rows the app imports (`wrote ... (5 rows)`) rather than the lexicon's terms.
- `lexicon setup` cancelled at a prompt (ctrl-C or ctrl-D) now stops at that step with a card of what the finished steps already wrote (the lexicon, seeded terms, packs) and says to run it again, since every step skips what is done. It failed with `input closed before the prompt was answered` and no word of what had been written. The summary carries `stoppedAt`, and the exit code is 1.
- `lexicon export json` writes what a lexicon file holds, without `scope` and `hits`. Those come from the merged view (which file a term came from, and this user's counts from `hits.json`), so a backup changed after every corrected prompt and an import elsewhere carried this machine's counts. `lexicon list --json`, `lexicon stats --json` and the MCP `lexicon://json` resource still report them.
- The capped `claude-md` table (MCP `lexicon://me`, the `voice-context` prompt) no longer splits a surrogate pair when the header and footer alone pass the cap. The cut fell at a fixed code unit, so half an emoji could reach the model as an unpaired surrogate; a cap under 4 characters also wrote more than the cap.
- `lexicon export macos` (and `exportLexicon` from code) removes the C0 control characters XML 1.0 cannot hold (all but tab, LF and CR) from a lexicon built in memory. Written as is, one made the whole plist unreadable. A pair left with an empty shortcut or phrase is not written, and a note says how many entries were changed.
- `lexicon export espanso` double-quotes every string. A trigger or name such as `yes`, `on`, `off`, `~`, `0o7` or `1:20` was written plain, which a YAML 1.1 reader (or 1.2, for `0o7`) reads as a boolean, null or number, so it no longer typed as written.
- `lexicon export espanso` and `macos` write a trigger or shortcut two terms share once, for the more used term, whatever the file order, and name the other on stderr. Both were written, and the tool expanded the alias to either. macOS shortcuts are compared ignoring case.
- CSV exports no longer carry spreadsheet formulas. A name starting with `=`, `+`, `-`, `@`, a tab or a carriage return was written as is, so opening the file in a spreadsheet ran it. `lexicon export csv` writes such a cell as text with a leading `'` (the spreadsheet escape) and says how many on stderr; `lexicon export wispr` leaves the pair out and names it, since Wispr Flow would keep the `'` as part of the word. Both keep LF line ends and no byte order mark, now documented, and `--json` `rows` counts the rows actually written.
- `lexicon export deepgram` adds `keyterm`, the list Nova-3 (Deepgram's current model) takes in place of `keywords`: the names as written, at most 100 (a conservative cap; Deepgram's own limit is not confirmed offline). `keywords` stays for Nova-2 and older, and a name that reads as one already listed once its colon becomes a space (`Win:2` next to `Win 2`) is now written once, for the more used term, and named on stderr.
- `lexicon export assemblyai` leaves out a name of more than 6 words, AssemblyAI's per-phrase limit as last documented (not confirmed offline), and names it and any name the 1,000-entry cap dropped.
- `lexicon export google` leaves out a phrase over 100 characters (Google's per-phrase limit) and writes at most 1,000 phrases, and `lexicon export azure` at most 500, the most used kept. Both wrote every canonical, so a large lexicon or one long name exported a request the API refuses. The vendor limits are as last documented and not confirmed offline; what was left out is named.
- `lexicon export whisper-prompt` and `openai` keep the line within the 224 tokens Whisper reads of a prompt. The cap was 100 names whatever their length, and the names are written most important first, so a long line lost exactly the names that mattered most when Whisper cut its start. Names are now kept, most used first, while an offline token estimate that errs high stays within 223 tokens; the rest are named on stderr.
- Exports say what a format left out to fit its target: one `lexicon: <format> export left out ...` line per kind on stderr, `dropped` under `lexicon export --json`, a note block from MCP `export_lexicon`, and the `X-Lexicon-Note` header of `GET /export/:format`. Library callers get the same from the new `exportLexiconWithNotes`.
- `lexicon serve --status` and the MCP `serve_status` tool count a `/health` reply as lexicon serve only when it has the server's fields (`ok` true, a non-empty `version` string and a whole-number `terms`), the check the browser extension makes. Any `{ ok: true }` used to count, so another program on the port was reported as the server; it now says something else answers on that port.
- `lexicon export assemblyai` lists at most 1,000 `word_boost` entries, the API's limit, keeping the most used names. It listed every canonical, so a large lexicon exported a request AssemblyAI refuses.
- Exports for dictation apps and STT engines write names in Unicode NFC. A lexicon file holding a decomposed accent (`Cafe` plus U+0301, as text pasted from a macOS file name often is) exported that form as the Wispr, Superwhisper, macOS and espanso trigger, which precomposed typed and transcribed text never matched; one alias in both forms wrote two rows, and a name in both forms was boosted twice in the AssemblyAI, Azure, Google, Deepgram and Whisper prompt exports. `json`, `text`, `markdown` and `claude-md` keep the file's own text. `lexicon export --json` counts `rows` the same way.
- `lexicon export --out` writes through a temp file and a rename, keeping the existing file's mode, so an export cut short no longer leaves a truncated file where the last good one was (`lexicon setup`'s export step writes the same way). It also refuses, with exit 1 and nothing written, an `--out` that is a directory (a bare EISDIR before) or that is the global or project lexicon file the export reads, directly or through a link: `lexicon export json --out ~/.config/lexicon/lexicon.yaml` replaced every term with the export.
- `lexicon export` (and the MCP `export_lexicon` tool, `GET /export/:format` and the SessionStart table) sorts names by a fixed English collation instead of the system locale. Under `LANG=sv_SE.UTF-8`, for example, `Äpple` sorted after `Zeta`, so the same lexicon exported in another order on another machine and `--limit` kept other terms. Spellings the collation calls equal (one name in two Unicode forms) are ordered by code units, so the order no longer depends on the order of the file either.
- Prompt hook: the quick check of a hand edit to a large global lexicon (served stale while the background parses it) now also gives a verdict for an edit outside the `terms:` list, such as a broken `version:` line or a bad `settings:` value, and reports a term the edit added or renamed whose canonical another term in the file already holds (which `lexicon doctor` fails). Both used to pass silently until the prompt after the background refresh, and a duplicate canonical never showed there at all. The check stays at a few milliseconds on a 5000-term file and never quotes the file's text.
- Browser extension: the Firefox build now requires Firefox 127 (`strict_min_version` was 121). Firefox grants an MV3 add-on's host permissions at install only from 127, so on 121 to 126 the chat sites and the local server stayed blocked until each was allowed by hand in `about:addons`. The minimum was raised rather than asking for the permissions at runtime. The manifest is built by `scripts/extension-manifest.mjs`.
- Browser extension: the stored API token is trimmed when settings are read, so a token saved with the spaces or newline around it (by an older Options page, or a settings patch) is no longer sent as is and rejected.
- Browser extension: in the Embedded mode the popup no longer probes `/health` on every open; no server is configured for that mode. Options > Test connection still checks the server.
- Browser extension: a `/health` reply counts as lexicon serve only when it has the server's fields (`ok`, a `version` string and a whole-number `terms`). Any `{ ok: true }` used to count, so another program on the port read as Connected and every correction was posted to it; now status says something else answers there and corrections use the embedded lexicon.
- Browser extension: Learn (`POST /learn`) waits up to 15 s and Sync (`GET /lexicon`) up to 10 s before reporting a timeout. Both used the 1.5 s timeout of a correction, so a Learn the server was still writing (it waits up to 10 s for the lexicon file's lock) and a Sync of a large lexicon read as timed out. Corrections, `/health` and `/stats` keep 1.5 s.
- Browser extension: after the server answers 401 to the stored token, the extension stops sending that token for 30 s, doubling with each further 401 up to 10 minutes, instead of sending it again with every normalize, Learn, Sync and popup open. Pairing or saving another token (or base URL) retries at once, and Options > Test connection always asks. The popup and Test connection say the token is being held back and for how long.
- Browser extension: the cached `/health` result is dropped when a request finds nothing listening, times out, or gets a 401 or 403, and is kept per base URL. Only saving settings through the background cleared it, so a server that stopped, or restarted with another token, was trusted for the rest of the 10 s cache, and a base URL changed in Options reused the old URL's result.
- Browser extension: the popup's per-site switch no longer empties the embedded lexicon on a fresh install. ## 0.5.6 (2026-10-18)

### Security

- MCP `trust_project` `trust` no longer succeeds on the agent's call alone. It asks the user through MCP elicitation, binds the approval to the file's hash at preview time, and refuses (or revokes) if the bytes change. Clients without elicitation get an error telling the user to run `lexicon trust` in a terminal. Before, an agent steered by a hostile repo could trust that repo's `.lexicon.yaml` itself and its text then reached every prompt.

### Added

- MCP `apply_suggestion` takes `suggestions`, 1 to 100 suggestions from `suggest_terms`, in place of `suggestion`, so an agent applies every suggestion the user accepted in one call. They are applied in order, and each run of alias, never and term suggestions bound for the same lexicon file is one `addTerms` write, where one call per suggestion re-read and rewrote the whole file each time. The result is `{ count, applied, failures, summary }`: each `applied` entry is what `suggestion` returns plus its `index`, each failure `{ index, kind, canonical, error }`, a refused suggestion does not stop the rest, and the call is an error only when nothing was applied. A batch write that fails is retried one suggestion at a time, so each failure names its suggestion. `suggestion` and its result are unchanged.
- `lexicon export --json` prints one document: `{ ok: true, format, terms, bytes, path }` after writing `--out`, `{ ok: true, format, terms, bytes, content }` with the export as a string without it, and `{ ok: true, formats }` (each `{ name, description, ext }`) with no format, plus `projectTrust`, `skippedProject` and `note` when an untrusted project lexicon was left out. - A plural keeps its "s". When a window minus its final "s" is an exact alias hit, or a closer match to the same term, only the base is replaced: "rotate the jots" becomes "rotate the JWTs", "three ollamas" becomes "three Ollamas" (it was "Ollama"), "the key pee eyes" becomes "the KPIs" (it was "KPI"). Thirteen commits, and a fix release rather than a routine one. 0.5.3 shipped a defect that throws away a term you had just written while telling you it saved it, and three more paths that lose a write without saying so. Everything below was reproduced before it was touched, and every regression test here was watched failing against 0.5.3 first.

Two published numbers moved in these notes without the matcher changing, and two defects are open. Both are explained under [Changed](#changed) rather than left for a reader comparing benchmark tables to discover.

### Security

- **Every write widened a lexicon from 0600 to 0644.** The temp file that the atomic write renames into place was created fresh under the umask, so the rename carried the looser mode onto a file the user had deliberately narrowed. A lexicon holds names: colleagues, clients, customers, projects. `resolveMode` now takes the mode an existing target already carries, sets it on the temp file before the rename, and creates under the umask only when the target does not exist yet. The two tests that pin this are skipped on win32, where Node reports 0666 for any writable file whatever mode was asked for; they were skipped rather than loosened, because an assertion weak enough to pass on all three platforms would stop catching the defect on the two that have permission bits.
- **Personal usage counts were written into the file a team commits.** `.lexicon.yaml` is tracked in git and the docs recommend committing it, and the prompt hook called `recordHits` on every corrected prompt, which rewrote that same file to bump a `hits:` counter. Four things followed, and all four are in this repository's own history: every one of the nine commits that ever touched `.lexicon.yaml` carried a `hits:` line that had nothing to do with its subject, including one about version numbers; a contributor gets a conflict on every word they happen to say; the counts are a record of which words the maintainer dictates most, published in a public repo; and because trust pins the sha256 of the content, everyone's dictation kept invalidating everyone's pin. A counter is per-user and a project lexicon is shared, so a project term's count now goes to `hits.json` beside the global lexicon, keyed by project file path and canonical, exactly the way `trust.json` already works. Global-scope counts stay in the global lexicon, which is already one person's file and in nobody's repository. There is no setting, because the counter belongs to the person who earned it in every case. `writeLexiconFile` enforces the rule for a project file rather than trusting nine call sites: every term's `hits` is forced back to what the file already says, and dropped for a term the file does not have.
- **The Windows tray app's UI Automation half has still never run on real Windows.** Restated from 0.5.3 because nothing about it has changed. Everything under `apps/windows/src/LexiconBar.App/FixEverywhere/` reads and rewrites text in whatever application has focus, through UI Automation and `SendInput`. It compiles, and 214 headless C# tests run in CI on Linux and on `windows-latest`, but no part of the UI Automation half has ever executed on a real Windows desktop. CI cannot close that gap: a GitHub runner has no interactive session, so there is no focused element, no foreground window and no caret. That is why no release ships the binary, and why [WINDOWS-APP.md](docs/WINDOWS-APP.md) lists what is unrun one line at a time and ships a manual test script.

### Fixed

- **A term written while a pack installed was lost, and both commands reported success.** The file lock's own comment said a lock held by a live process on this host is never broken however old it is. The code broke it on age alone and exempted only the current process's own pid. That became reachable in 0.5.3, where `installPack` went from seventy short locks to one long one: measured end to end on a three thousand term lexicon the install holds for around a minute against a thirty second staleness rule, and the schema cap is five thousand terms. A `lexicon add` arriving half a minute into a `lexicon pack install` broke the live lock, wrote, and printed success; the install then renamed its own copy over the top. Both exited 0 and the term was gone. Liveness is now the whole rule for a lock this host wrote, a holder refreshes its own lock's mtime while it works so age means something again, and an add that arrives mid-install is refused out loud instead of being silently discarded.
- **The trust registry had no lock, so concurrent project adds crashed and left repositories written but unregistered.** Six `lexicon add --project` runs in six repositories: one crashed renaming the temp file, and three wrote their `.lexicon.yaml`, reported success, and were absent from `trust.json` afterwards. Absent from the registry means untrusted, which means the project's terms are silently skipped on every prompt from then on, with nothing anywhere saying so. `serve.json` had the identical gap, and it holds the bearer token for the local HTTP API, so the loser of a first-run race walked away with a token the server answers 401 to. Both files are now read, decided about and written inside their own lock.
- **Uninstalling a pack read and wrote outside the lock, losing a racing term thirteen times out of thirteen.** `uninstallPack` read the lexicon, decided which terms survived, read the hits sidecar and only then wrote, none of it locked: the fourth instance of the class the install lock was added to fix, sitting directly below the one that was fixed. Each file is now read, decided about and written inside its own lock, and the project and global files are taken one at a time, because one lock around both is the shape that risks a wait with no end. `runEdit` had the same gap around its create-if-missing that `runInit` was already fixed for.
- **A symlinked lexicon path was silently replaced by a regular file.** A lexicon path is often a symlink into a dotfiles repository or a cloud-synced folder. The first write severed it and the real file never saw another term, while reads went on working against the new regular file, so nothing looked broken. The write resolves the real path first now.
- **Three smaller lock defects, all executed rather than reasoned about.** The temp file was `<target>.tmp` for every writer, so two writers inside the critical section together corrupt a rename rather than merely losing an update; it carries the writer's pid now. The in-process queue was unbounded, so two chains taking two paths in opposite orders hang forever; it fails with something a person can read. And the backup was one generation deep, which for a lexicon means the prompt hook's next hit counter destroys it seconds later; a second copy at `<path>.1.bak` is refreshed only once it is fifteen minutes old, so no amount of ordinary churn can reach it.
- **The matcher stopped correcting every canonical that ends in a numeral, and duplicated the version instead.** The edge guard added in 0.5.3 refused any phonetic window that started or ended on a numeral, because a numeral contributes no letters and so no length penalty can price it. That is just as true of the numeral in the term's own name, which was not considered, so "clawd 4" no longer reached `Claude 4` at all. Worse, the narrower window was still allowed, so a lexicon holding `Kubernetes 1` turned "cooper netties 1" into "Kubernetes 1 1". Claude 4, GPT-4, Llama 3, Postgres 16, Node 22, Vue 3: a developer lexicon is full of the shape. The window's edge is tested against the alias now rather than on its own, so it may span a numeral the canonical also carries, while "cooper netties 2" still cannot reach plain `Kubernetes`.
- **Indented code blocks are skipped, with the caveats [MATCHING.md](docs/MATCHING.md#indented-code-blocks) states.** 0.5.3 taught `skipCode` about Markdown's indented code block but decided whether a line looked like a list item from the candidate opening line alone, so one bullet-looking first line stopped the block opening at all and the same three lines were skipped or rewritten depending only on the order they were in. Still corrected, and known to be: a run hanging under a table row, and one whose block quote depth differs from the line above it.

Aliases the user listed are exempt. Which spans win is unchanged and both benchmarks are identical on every quality metric; the alias mean confidence moves from 1.000 to 0.995, which is the change being visible.
- **The plain-word bar did not see a word with a hyphen in it.** `plainWord` was `/^\p{Ll}+$/` and the tokenizer keeps the hyphen, so "per-category" arrived as a token the fuzzy pass held to no bar at all: neither a plain word nor a multi-token window, and rewritten to `TermCategory` at 0.83. ## 0.5.3 (2026-09-20)

Thirty-four commits, most of them written after a fresh-user walkthrough and three rounds of review. The shape of the release is confidentiality and data loss: both desktop apps were reading the text of every field you focused before deciding whether they were allowed to, and six separate paths could throw away something you had dictated or written. Everything below was reproduced before it was touched, and every regression test here was watched failing against the unfixed code.

### Security

- **Both desktop apps read the text of every focused field before deciding whether they were allowed to.** `FocusWatcher` pulled the focused element's full value and cached it, and the poll refreshed that cache four times a second on Windows and twice a second on macOS. The exclusion list and the secret-field heuristic ran a layer above, in `FixEngine`, where all they could do was decline to build a detector for text the process already held. So a password manager's field, a vault note or a TOTP box in an app that was not on the exclusion list sat in memory for as long as it held focus. Nothing was sent anywhere and nothing was logged, so the exposure was a crash dump or an attached debugger, which is exactly the reach the threat model says we do not give it. `SECURITY.md` and the Windows app both claimed the opposite. The decision has moved in front of the read on both platforms: `LexiconBar.Core/FieldGate.cs` and `LexiconBarKit/FieldGate.swift` split a field into the metadata the accessibility tree exposes about it and the single call that pulls the user's text, and decide on metadata alone, so a refused field is never asked for its value on any of the three read paths. `FieldGateTests` drives a field that counts how many times anything asked for its value and asserts the count stays at zero through seven refusal cases.
- **On macOS the probe that decided whether a field was editable was itself a read.** `isEditableText` settled the non-text-role case by copying `kAXValue` to see whether it came back a string, so the user's text entered the process before any refusal could run, on a path that executed for every focused element. `couldBeEditableText` decides from attribute names instead, and whether the value is really a string is answered by the gated read.
- **Turning "Fix everywhere" off left the watcher reading every field and merely declining to correct it.** That switch is the mitigation `SECURITY.md` offers as the last resort, so it has to mean what it says. Off now stops the watcher on both platforms: no focus resolution, no event read, no poll, and the field it currently holds dropped on the spot. Which app is in front is still tracked, because that is metadata.
- **Excluding an app on macOS never reached the read gate.** `@Published` emits from `willSet`, and the sinks in `startFixEverywhere` discarded the value they were handed and read `settings.exclusions` back off the object, so the list pushed into `FixEngine` and on into `FocusWatcher` was the one from before the change. `setExclusions` then found it equal to the list it already held and returned early, and the field in the app the user had just excluded went on being read, POSTed to `/normalize` and rewritten. `Settings` gains `fixSettings` and `fixSettingsChanges`, a `CombineLatest4` that carries the new values through, and `AppDelegate` has one subscription that reads nothing back.
- **The undo hotkey was the one path where excluding an app mid-focus stopped neither the read nor the write.** `performUndo` and `PerformUndo` went straight to the field's value and consulted the gate afterwards, on both platforms. Both go through the gate first now, and a refusal drops the ledger entry with it.
- **On Windows, measuring the caret ran two calls ahead of the gate.** `Settle` called `CaretEnd` before the refusal check, and measuring the caret means measuring the document in front of it. The refusal runs first now, and `CaretEnd` and `SelectionMatches` take the same `MaxFieldLength` cap as every other read instead of `GetText(-1)`.
- **Un-excluding one app admitted its whole vendor.** `AppExclusions.include` deleted the rule that matched rather than the entry the user clicked, so re-enabling a single 1Password process removed `com.1password.*` on macOS and `1password*` on Windows. It removes only the exact entry now and returns the rule that still covers the app, which the tray names instead of showing a switch that springs back.
- **An emptied exclusion list on Windows said nothing.** It is one textbox that a single Ctrl+A can clear, and clearing it used to lose terminals, `lsass`, `logonui` and every password manager with no indication at all. `AppExclusions.IsEmpty` now drives a warning in place of the usual hint and a confirmation before saving one. An empty list still means "exclude nothing", the same as on macOS.
- **The two Windows security decisions now live where a test can reach them.** `LexiconBar.Core.Tests` references `LexiconBar.Core` and nothing else, because `LexiconBar.App` targets `net8.0-windows` and cannot load on the Linux runner that gates this repo, so a decision inside the App project had no test that would go red if it were reordered back. `ReadPolicy` holds the master switch and the exclusion list together and answers both what may be read and what the watcher must let go of; `UndoPlanner` holds everything the undo hotkey decides before it touches the field. Eleven of the nineteen new tests fail against the reversion they cover.
- **The Windows tray app still ships unverified, and should be treated as a preview.** Everything under `apps/windows/src/LexiconBar.App/FixEverywhere/` uses UI Automation and `SendInput` to read and rewrite text in whatever application has focus. It compiles, and 214 headless C# tests run in CI on Linux and on `windows-latest`, but no part of the UI Automation half has ever been run on a real Windows desktop. CI cannot close that gap: a GitHub runner has no interactive session, so there is no focused element, no foreground window and no caret. That is why no release ships the binary. `docs/WINDOWS-APP.md` carries the `gh run download` line for the CI artifact, says which parts are reasoned rather than measured, and should be read before you grant this app anything.

### Fixed

- **Concurrent writes to the lexicon silently lost terms.** The rename was atomic but the read-modify-write around it was not, and five writers share these files: twelve concurrent `lexicon add` calls each printed `created TermN` and left one term behind. Every read-modify-write now runs inside a lock file taken with `O_CREAT|O_EXCL`. It works between processes, it is re-entrant so a nested `writeLexiconFile` does not deadlock, a lock whose owner pid has exited is broken at once (Ctrl-C and crashes), one nobody can attribute expires by age, and a writer that still cannot get in throws rather than overwriting. `recordHits` is the only caller that swallows that, because a lost hit count is bookkeeping and it may never throw by contract.
- **Three callers above the lock still read the lexicon, decided something, and wrote the whole document back.** The write took the lock, so the file always stayed valid and nothing ever looked broken, which is what let the lost update hide. `installPack` rewrote `settings.packs` from the snapshot the last `addTerm` returned, so a term someone else added during the loop was renamed away; `runInit` checked `existsSync`, wrote, then appended the example comment, so two inits racing both passed the check and an add landing between the write and the append was read back without the comment; and `runReview` merged against an already stale copy when a writer landed between its re-read and its write, while reporting success. `runReview` is locked only for the digest check, re-read, merge and write, because holding the file open for as long as someone reads their terms would block every other writer on a human.
- **One import of a non-UTF-8 file left the lexicon unparseable with no backup, and every message the product then showed was false.** `lexicon import` read every file as UTF-8. A UTF-16LE file, which is what PowerShell's `Out-File` and Notepad's "Unicode" option write, arrived with a NUL in every other byte and died against the schema naming the *destination* lexicon, so the error blamed a file the user had never touched. A Latin-1 file was worse: it imported with exit 0, no warning, and recorded `Caf<U+FFFD>` as the canonical spelling of a word with an acute accent, so a tool whose whole job is getting spelling right had stored the wrong spelling permanently and reported success. And the garbage was written before validation ran, with no backup, leaving a lexicon that `list`, `stats` and `add` all refused to read. `importers/encoding.ts` now decides the encoding from the bytes before any parser sees them: UTF-16 is unambiguous, from a BOM or from the NUL in every other byte, so it is decoded in either endianness and the PowerShell case simply works; an 8-bit encoding is not unambiguous, since Latin-1, Windows-1252 and KOI8-R are the same bytes meaning different letters, so it is refused by the name of the input file with the `iconv` and PowerShell commands that convert it. UTF-8 with or without a BOM comes back byte-identical to what `readFile(p, 'utf8')` returned before. `importLexicon` also refuses any term carrying U+FFFD, which covers callers that hand it a string rather than bytes. The serialized bytes now go through the reader's own parse-and-validate before anything is replaced, and the previous contents are kept at `<path>.bak`.
- **With a lexicon that would not parse, `doctor` told the user there were no terms and to run `lexicon setup`.** Both sentences were false: the file had terms, setup cannot repair a parse error, and running it exits 0 having done nothing. The MCP `lexicon_doctor` tool handed an agent the identical dead end with `ready: false`. A file that exists but will not parse is now its own verdict, ahead of the empty-lexicon one, quoting the parse error and pointing at `lexicon edit`. Both the check line and `nextStep` lead with their command, because rendering caps a line at 200 characters and an absolute path can eat most of it.
- **`lexicon normalize` printed the parse error to stderr and exited 0 with the text unchanged**, which made "no corrections were applied" and "nothing needed correcting" the same answer. stdout still round-trips the input byte-exactly, because a broken lexicon must not damage a pipeline, but the exit code is 1.
- **The hook went quiet instead of saying the lexicon was broken.** A file that does not parse threw all the way out to `main()`, which writes one line to stderr and exits 0. Through Claude Code that line goes nowhere anybody looks, so corrections simply stopped and nothing said why: the user's first clue is that their company name is wrong again. The problem now goes out through the one channel the hook is already allowed to use. It tells the agent the file does not parse, quotes the parse error and names `lexicon edit`, on both hook events. The hook still exits 0 and still never touches the prompt.
- **`voice --toggle` deleted finished recordings.** Every toggle capture is spawned with `-t 600`, so a recording nobody stops ends itself at ten minutes. The next press then found a pid that was gone, called the state stale, deleted the WAV without ever opening it, printed "recording" and exited 0. A complete, finalized ten-minute capture was removed unread. A recorder that is gone is now inspected before anything is decided: the audio is transcribed whatever killed the recorder, with the length taken from the bytes rather than from a wall clock that counts the time the recorder was dead, and a capture with nothing usable in it is reported with ffmpeg's own last lines and the microphone-permission hint.
- **Four further ways a recording was thrown away on a guess.** A capture was deleted before anyone knew whether anything had been heard, because `cleanTranscript` turns `[BLANK_AUDIO]` into the empty string and so does a wrong `--lang` or a model too small for the speaker: a ten-minute 19.2 MB capture reached exit 3, `(nothing heard)` and an empty directory. `recoverDeadRecorder` could delete the WAV of a recorder that was still running, because a per-pid lookup that says "not yours" about a live pid is one command line read back and PowerShell folds a long one exactly where the capture's path sits. "An empty process list means cannot tell" was documented and not honoured, so on a host with no `ps` five minutes of live audio was abandoned under a second recorder. And the RIFF pad-byte walk stepped to the padded offset first, where one byte into a real id reads as printable ASCII often enough to refuse 48 of 128 capture sizes, swept rather than sampled. Nothing deletes a capture that holds bytes any more; `discardOrKeep` removes only a zero-byte placeholder.
- **A recycled pid could send the stop signal to a stranger's process.** A pid is unique only while its process lives, and `isAlive` cannot tell a stale state file from a live recorder. A start that died between spawning ffmpeg and writing the pid down also left a recorder nothing could stop, and the old code cleared the state and started a second one, so two competed for the microphone until the first reached the end of its own `-t 600`. `makeProcessDescribe` and `makeProcessList` read the process table through the existing exec dependency, `ps` on Unix and `Get-CimInstance` on Windows, with a literal filter so no caller-supplied path is ever interpolated into a shell. A live pid is confirmed before it is signalled, an orphan is found by the capture it is writing and transcribed rather than abandoned, and where the process table cannot be read at all both fall back to trusting the pid.
- **On Windows every toggle recording under about eight seconds was lost outright.** ffmpeg buffers 256 KB, so a capture killed early left a zero-byte file rather than a truncated one. Measured against ffmpeg 9.0.2. `-flush_packets 1` fixes it, the stop no longer claims to have finalized the WAV header when it cannot (Node maps every signal to `TerminateProcess`, and a detached recorder stopped by another process shares no console, so a real interrupt cannot be delivered), and the WAV check parses the container instead of trusting a size above 44 bytes.
- **The Windows write path could leave half a correction in a field with no undo and tell the user the write had failed.** `Keyboard.Send` issued one `SendInput` per 400 INPUT records, which is 200 characters, while the comment above the loop claimed the non-interleaving guarantee a single call gives. A later call failing left the earlier ones in the field, the engine found the field no longer held what the plan was made from, tripped its guard and reported "field changed" while half the replacement sat there, the user's own span was gone and `_undo.Record` had never been reached. There is one `SendInput` per write now, never a loop, capped at 1000 key events, with backspaces and their retype in the same call so the deletion can no longer succeed alone. A replacement longer than the cap goes through `ValuePattern.SetValue`, which replaces the whole value in one call and cannot half-finish. `Type` and `ReplaceTail` return how much landed rather than a bool, and `PartialWrite` computes what the field must hold when n of m key events landed. Undo consumes its ledger entry only after the write succeeds; it used to take the entry first, so an undo that did nothing threw away the only record of the correction.
- **The macOS write path had the same bug and a worse shape.** The keystroke rung posted CGEvents in chunks of twenty UTF-16 units and accounted for none of it: a chunk whose CGEvent came back nil was skipped in silence while the chunks after it went out anyway, so a failure in the middle left a hole in the middle. `UnicodeTyping.post` now builds both key events for a chunk before it posts either and stops at the first chunk it cannot build, and chunk boundaries step back off a surrogate pair, so what landed is always a prefix and every stopping point is a whole string.
- **The recovery for a half-written correction was racing the keystrokes it recovers.** `SendInput` and CGEvent posting both queue, and the target app consumes on its own message loop, so the count that comes back is records inserted rather than characters consumed. The partial-write path took one immediate reading and demanded it equal the single state the count predicted, so the two likeliest outcomes were both wrong: if the app had not started on its queue the field looked untouched, the whole-value write went ahead and the queued characters landed on top of it, and if the app had consumed a different number the engine answered that it could not account for the state and recorded nothing. `KeystrokeSettle`, in the portable core on both platforms, watches the field across the same 0.6 s window the success path waits out and identifies the state from what the field holds rather than from what the count claimed, keeping the count only as a bound on how much can have arrived. A half-landed write then falls through to the whole-value write, which repairs it, and where that cannot run the ledger gets an entry describing the half-written state before the user is told anything, so undo puts their own text back and the message says only part of the correction went in. Keystrokes the system accepted that never appeared are deliberately not written over, and the state they would produce is recorded so a late arrival is still reversible. On macOS, `undo.take` cleared the ledger entry before the write was attempted, so an undo whose write did nothing threw away the only record of the correction; the entry is consumed on success only.
- **The setup wizard's repo harvest was teaching the lexicon to rewrite ordinary English.** Step 3 ranked PascalCase symbols by how often they appear in source and generated each one an alias by splitting the camel case, so `InlineData` arrived carrying `inline data` and `TimeInterval` carrying `time interval`, and from then on "let us set a time interval of five minutes" came back with a class name in it. Measured over forty-five ordinary dictated sentences across four repos, the list this step builds by default damaged 5.0% of them and the twenty-name version 10.6%. `harvestRepo` stops inventing word boundaries: an identifier gets no aliases at all, and a name without a separator of its own keeps only the single-word suggestions, so "Ashlr.AI" and "pasture-notes" keep "Ashlr AI" and "pasture notes" while "Lexicon Bar" is gone because "LexiconBar" never said where its words break. The ranking was wrong too: a name is proposed only when the repo says it somewhere other than its own source, which means a manifest, a README sentence, the git log, the directory name or a dot-TLD brand. With the symbol flood gone the wizard's minimum count of five was only hiding real names, so it drops to two, and a three-file project that used to yield nothing but its own directory name and the git author now finds four of the five services it actually runs on. Same corpus after the change: 0.6%, and the one remaining case is this repo's own LexiconBar, a real product name matched phonetically rather than through a generated alias.
- **Text that quotes a misspelling is no longer flattened into one spelling.** The hook rewrote "the chips Mason Wiatt / Mason Wyat" into two copies of the canonical, and the sentence stopped saying anything. That matters well past one report, because the lexicon file, the docs tables, the onboarding screen and any conversation about which words to add all quote the misspellings on purpose. The obvious rule, never collapse two spellings into one, is wrong: "the reddis and red iss instances are the same box" is one person dictating one word twice and both halves must be fixed. The guard was built, reviewed, rebuilt, reviewed and rebuilt again, and the final version asks a closed question rather than an open one. The gap between two mentions must be made *only* of words about writing rather than merely contain one, so a single word about the world ("caching", "upgrade", "scripts", "again") makes it dictation whatever cues sit beside it; a lead-in counts only when the passage opens with it; the canonical anchors in any spelling that folds to it, so "it's ashlr.ai, not Ashler" survives; a single newline no longer ends a passage, which had silently disabled the guard for every markdown list and YAML block it exists to protect; and the refusal is per run of linked mentions rather than per block, because sentence bounds cannot be got right when a period follows a digit or an abbreviation.
- **The quoting guard is now pinned by a generated suite rather than by hand-picked lists.** Both earlier versions tested whether a cue word sat *somewhere near* the mentions, first anywhere in the sentence and then anywhere inside a thirty-character gap, and "somewhere near" is an open test when `not`, `heard`, `wrote` and `means` are ordinary English. `tests/enumeration.property.test.ts` generates the round trip from parts: 56 connectives in both orders, three canonical spellings per term, quoting, prose wrapping, tables, YAML, markdown lists and multi-line blocks, mirrored by ordinary dictation and by every quoting shape with the canonical removed. Quoting must keep both spellings, dictation must lose the garble, and neither number can be traded for the other in silence. Against the guard as it stood, 27,873 of 36,540 generated quoting cases failed and 24 of 243 dictation cases failed. It now passes 36,540 of 36,540 and 243 of 243, with nothing skipped. Both benchmarks were run and neither moved, which is the point: the corpus cannot see any of this. The guard also walked every span for every sentence, which was quadratic on the 1 MB the local API accepts; one moving cursor now costs 59 ms.
- **Two spans the matcher was widening past the word it matched.** A phonetic window grew one token past the garble whenever the extra token made no sound of its own. Phonetic confidence is a ratio of letter counts, so a bare numeral costs nothing at all and a two-letter abbreviation costs almost nothing: the wider window stayed above the threshold and then won overlap resolution on span length. "cooper netties i.e. Terraform" came out as "Kubernetes. Terraform", and "1. cooper netties 2. Cooper Netties" lost the 2. An inexact multi-token window now never starts or ends on a numeral or a spelled-out abbreviation. The guard is lexical rather than phonetic because scoring cannot tell these cases apart: a trailing "ai" adds nothing to a metaphone key either, so refusing every window whose edge token adds no key would lose "opin ay" to OpenAI and "ashlur ay" to Ashlr.AI. It is the phonetic pass only, since "b 2 b" and "auth 0" are aliases users list and the fuzzy pass compares only windows of the same token count.
- **Indented code blocks are skipped now.** `skipCode` did not know Markdown's other code block, a run of lines indented by four spaces or a tab, so the hook rewrote the indented repro inside a bug report about the bug above. The rule is deliberately narrower than CommonMark: a block needs a blank line above it and a column-zero, non-list, non-quote line above that, so a wrapped paragraph line, a list item's indented continuation and a nested bullet stay ordinary text. Indented code inside a list or a block quote is still corrected.
- **The landing page told visitors this was version 0.5.0** while `package.json` said 0.5.2 and npm served 0.5.1: three numbers live at once for a project whose pitch is getting details right. The version check only ever matched `#vX.Y.Z` pins, so a version written as a constant was invisible to it, which is how `web/lib/site.ts` drifted two releases behind without anything noticing.
- **The README's "How it works" block printed output the command does not produce.** It showed "cooper netties" resolving through the phonetic tier at 0.85, but that string is an explicit alias in the developer pack, so it never reaches that tier: the real answer is alias at 1.00, and the block was illustrating a tier with an example that skips it.

## 0.5.2 (2026-09-20)

Windows and Linux are in CI for the first time, running the real platform tools rather than fakes. That found a bug that had been breaking every Windows install since the hook existed, and a test that had never tested the thing it claimed to.

### Security

- **`lexicon install claude --apply` on Windows wrote a hook command pointing at a file that does not exist, and reported success.** `launchCommandLine` quotes the hook path and escapes the characters a POSIX shell would otherwise eat, and the backslash is one of them. On Windows the backslash is the path separator and nothing else, so `C:\Users\me\...\hook.js` went into `settings.json` as `"C:\\Users\\me\\...\\hook.js"`. Every `lexicon install claude --apply` on Windows has been doing this for as long as the hook has existed: the correction hook was never actually installed, while the CLI said it was, and nothing downstream noticed. Quoting on Windows now escapes nothing, which is safe because a Windows filename cannot contain a `"`, and escaping `$` or a backtick would corrupt a path that legitimately holds one. The platform is a parameter rather than read off the host, and the absolute-path check uses `path.win32` so it answers for the OS being targeted.
- **The printed `claude mcp add` line carried the same defect.** `cmd-install.ts` holds a second copy of the POSIX quoting, used for the instruction printed when `--apply` is not given, so the command a Windows user copied out of the terminal named `"D:\\x\\dist\\mcp\\server.js"` rather than the file. Same fix and same reasoning. `quoteArg` was also handed to `Array.map` bare, so the array index arrived in its `platform` argument.
- **The test asserting that term harvesting never reads `node_modules` had been passing without asserting anything.** `harvestRepo` walks a user's repository to propose terms, and `node_modules` is on its always-ignored list. The fixture that proves the skip lives under a `node_modules/` path, so a contributor's global gitignore kept it out of `git add` and it was never committed: CI cloned a fixture with no vendored file in it, harvest had nothing to skip, and the assertion passed for the entire life of the test. For a tool that reads your code, "it does not look in there" is a promise that has to be exercised, and this one never was. The fixture is force-added, and both tests now read it and assert it is present before asserting it was skipped, so if it goes missing again they fail loudly instead of going quiet.
- **The Windows tray app ships unverified, on purpose, and should be treated as a preview.** Everything under `apps/windows/src/LexiconBar.App/FixEverywhere/` uses UI Automation and `SendInput` to read and rewrite text in whatever application currently has focus. It compiles and its decision rules are tested headlessly, but no part of it has ever been run on a real Windows desktop. CI cannot close that gap: a GitHub runner has no interactive session, so there is no focused element, no foreground window and no caret. Read `docs/WINDOWS-APP.md` before you grant it anything.

- **A Windows tray app** under `apps/windows/` (C#, .NET 8), built and tested from a Mac. `LexiconBar.Core` targets plain `net8.0` and may not reference UI Automation, WinForms or Win32, which is what lets its xunit suite run headless on a machine that cannot launch the app at all. The burst detector and text-alignment suites are case-for-case ports of the Swift ones, so the four text-corruption bugs found the hard way on macOS are pinned here before Windows ever runs the code. ### Added

### Fixed
- **`lexicon doctor` could name a different whisper binary than `lexicon voice` would actually run.** The sync PATH lookup iterated directories in the outer loop and candidate names in the inner one, while the async lookup did the reverse, so on a machine with `whisper-cpp` in `/opt/homebrew/bin` and `whisper-cli` in `/usr/local/bin` doctor reported one and voice ran the other. Both forms now use name-preference order: every PATH entry is tried for the first candidate name before the second name is considered at all. The two are unified in `src/util/which.ts` and `tests/which.test.ts` asserts they agree.
- **Streamed dictation was dropped entirely.** macOS's own dictation, Wispr Flow's streaming mode and an app's built-in microphone button do not paste a finished phrase: they insert a word at a time. The gaps between spoken words are routinely longer than the 700 ms settle delay, so each word ended its own run, was judged `too short (1 words, N units)` and was thrown away; then so was the next, and the next. Measured live in TextEdit with words arriving 900 ms apart: nine consecutive skips and a sentence left completely uncorrected, while the same words arriving 250 ms apart were corrected normally. The feature only ever worked for paste-sized insertion, which is a much narrower promise than "works with any dictation". `BurstDetector` now separates a verdict from acting on it: a run that has produced at least one word-sized insertion is held open (`Outcome.coalescing`, and the baseline does not move) until the field has been quiet for `runQuietMs` (default 1500 ms, longer than a pause between words, shorter than the end of a sentence), so the words accumulate into one burst and are corrected together. `maxRunMs` (default 12 s) caps a run so continuous dictation is still corrected periodically. Two things keep this from swallowing ordinary input: key-by-key typing never produces a `minChunk`-sized insertion, so it is still refused with `typed, not dictated` however slowly it is typed; and a single insertion that already reads as a burst is a paste with nothing to wait for, so it still fires at the settle delay. Verdicts that silence cannot change (multi-paragraph, field too long, an insertion point that cannot be located) are refused immediately as before.
- **Fix everywhere did nothing in the Codex (ChatGPT) desktop app.** Dictating into its composer left `My company, Ashler, deploys Stéphan Versel.` uncorrected, with no log line at all, because LexiconBar never saw a text field there: the app answers `kAXErrorNoValue` for `AXFocusedUIElement` and its whole window reads as six nested empty `AXGroup`s. It is Chromium-backed but rejects `AXManualAccessibility` (`kAXErrorAttributeUnsupported`), the switch Electron uses and the only one LexiconBar sent. Writing AppKit's `AXEnhancedUserInterface` instead wakes it, and the composer turns out to be an ordinary `AXTextArea` with `AXValue`, `AXSelectedText` and `AXSelectedTextRange` all settable, so this was never a field we could not write, only one we could not see. `FocusWatcher` now sends that second nudge, and the same burst is corrected in place: `My company, ashler, deploys on versal and cuban eats` → `My company, Ashlr.AI, deploys on Vercel and Kubernetes`, via the keystroke strategy in 299 ms. What actually wakes the app is the request rather than the attribute: the write reports `kAXErrorNotImplemented` and the tree appears anyway, while the 500 ms focus poll had been reading the same app for minutes without waking it, so the error code is logged rather than acted on. The nudge is sent only to an app that has already reported no focused element, at most once per process, because where the attribute *is* honoured enhanced mode makes AppKit animate window frame changes. Cursor and VS Code remain invisible even after it, and now say so in the log rather than failing silently.
- **Fix everywhere could corrupt text it was asked to correct.** Seen live in TextEdit: a document holding "ping Ashlr.AI about the cooper netties rollout" received the burst "ping ashler about the cuban eats rollout on versal" in front of it and ended up as `ping ashler about the cKubernetes rollout on versalping Ashlr.AI about the cooper netties rollout`: the replacement one character late, the leading `c` of "cuban" orphaned, and the other two corrections in the same burst missing entirely. The cause was in the pure diff: `TextDiff.delta` locates an insertion by stripping the common prefix and suffix, and both strings begin "ping ", so those five units were credited to the old text and the reported window started five units late and ran five units into text the user already had. The window was textually consistent: `substring(fullText, range) == burst.text` held, so every downstream guard passed and the rewrite was spliced across the boundary. `delta` now also measures how far the window could slide and still produce the same result (`slideLeft`, `slideRight`) and takes an optional `caretEnd`, the insertion point, which picks the window that actually arrived (`anchored`). `BurstDetector.settle(at:caretEnd:)` takes the caret from the focused element and refuses outright (`skipped("insertion point is ambiguous")`) when the insertion cannot be located and nothing pins it down: no correction is much better than a correction spliced into the middle of someone's sentence. The check runs last, so ordinary skips keep their real reason.
- **Fix everywhere now refuses to write into a span it has not verified.** The rewrite selects the burst range and writes `AXSelectedText`, trusting the app to mean the same UTF-16 offsets. It now re-reads `AXValue` immediately before the destructive write (the range round-trip polls for up to 300 ms, and the field is live throughout), and reads `AXSelectedText` back after selecting: unless the selection holds *exactly* the text the plan replaces, the two range strategies are skipped and the whole-value write takes over, which is computed from the pre-write snapshot alone and so cannot be misaligned. The same check is repeated immediately before the keystroke strategy. A write that lands but produces something other than the plan leaves the field alone rather than writing again on top of it, and says so. 13 new tests in `LexiconBarKit` covering the exact corrupting shape, caret anchoring, a caret that cannot be believed, slide measurement in both directions, several replacements in one burst with the user's own text on both sides, a stale snapshot and a burst range that no longer holds its text.
- **The macOS Accessibility grant survives a rebuild.** TCC binds a grant to the app's designated requirement, and an ad-hoc signature has no certificate to name the app by, so the requirement was `cdhash H"…"`: a different value on every build. The row in System Settings kept its switch on while tccd denied the app with `Failed to match existing code requirement for subject ai.ashlr.lexiconbar`, and toggling the switch did not rebind it; only removing the row with **−** and adding the app again did, once per build. New `scripts/make-signing-identity.sh` creates a self-signed code-signing certificate in a keychain of its own (`LexiconBar Local Signing`, RSA 2048, ten years, `basicConstraints=critical,CA:false`, `extendedKeyUsage=codeSigning`), and `scripts/build-macos-app.sh` signs with it when it is there. The requirement becomes `identifier "ai.ashlr.lexiconbar" and certificate leaf = H"<cert>"`, which depends on the certificate rather than on the bytes, so it is byte-identical across builds: two builds of a genuinely different binary (cdhash `e0184aa0…` then `1fdb6b1b…`) produced the same line, and the second satisfied the first's requirement under `codesign --verify -R`. - **LexiconBar `--status` told the truth about Accessibility.** `AXIsProcessTrusted()` answers for the *responsible process*, which for anything started from a shell is the terminal, so `--status` inherited the terminal's grant: a freshly built `.build/release/LexiconBar`, a binary that cannot hold a grant of its own, reported `axTrusted: true` at the same moment the unified log showed the GUI-launched bundle being denied (`kTCCServiceAccessibility auth_value: 0`). The one person most likely to run `--status`, someone debugging why Fix everywhere does nothing, was told the opposite of the truth. Launched by the window server it reports `AXIsProcessTrusted()` as before. "Terminal-launched" is decided by the parent process (a window-server launch is parented to launchd) *and* by a controlling terminal, because a shell script, a CI job and an agent harness all run with pipes and no TTY and still inherit the shell's grant: `isatty` alone was tried first and reproduced the original bug from a pipe-only shell.
- **LexiconBar now answers the Accessibility question from a terminal, honestly.** The running app writes its own trust state, pid and a timestamp to `~/Library/Application Support/LexiconBar/state.json` (mode 0600, written to a temporary file and `rename(2)`d into place) at launch, when the focus watcher starts or stops, when the grant changes under it, and every 30 s otherwise. `--status` reads it and prints a second line: `Accessibility (menu bar app): trusted|not granted (as of <relative time>)`, falling back to "not running" when the file is missing, when it carries the `running: false` record written on quit, or when it is more than 5 minutes stale. `--status --json` exposes the same as `axAppTrusted`, `axAppRunning`, `axAppStateAge`, `axAppStatePath` and `axAppStatus`; `axAppTrusted` is what a script or an agent should read. - LexiconBar quit cleanly on SIGTERM. AppKit runs `applicationWillTerminate` for the Quit menu item but not for a signal, so `kill` and a logout took the app down with none of its cleanup: the `lexicon daemon` and `lexicon serve` children outlived it, and the new state file was left claiming the app was up until it aged out. ### Security
- **A hostile repo could read text into your agent through the tool that exists to stop exactly that.** The trust model tells an agent to call `trust_project` rather than open an unreviewed `.lexicon.yaml` itself, so the file's contents never reach the conversation. A file that failed to *parse* defeated it: the `yaml` package embeds the offending source line verbatim in its error message (`prettyErrors`, on by default), and `trust_project` returned that message unsanitized. A repo could put instructions on the line before a deliberate syntax error and have them read into the agent's context the moment it did the safe thing. Escape sequences and bidi overrides in the *path* leaked the same way, through the file path, the registry path and the summary strings, which were echoed raw. Every string the tool echoes now goes through `sanitizeForDisplay`, on the throwing branch as well as the returning one. `tests/mcp-trust-injection.test.ts` runs the real server against a real hostile file on disk rather than a mock, because the leak lived in the seam between the YAML parser and the tool result.
- **Fix everywhere reached into password managers it did not exclude.** The default exclusion list named only Terminal, iTerm2, Warp, Apple Passwords, 1Password and Keychain Access, while docs/MACOS-APP.md claimed flatly that "password managers are excluded by default". Bitwarden, Dashlane, LastPass, KeePassXC, NordPass, Enpass, Proton Pass, Keeper, RoboForm and Strongbox were all missing, and the secure-field check only refuses the literal masked input, so in any of them an item's notes, a custom field holding a secret, a TOTP seed box or a vault search field echoing a saved username was fair game, and Fix everywhere is on by default. The list now covers those managers (mostly as vendor prefixes, because an exact list is wrong the moment a vendor ships a new bundle id; Keeper alone has shipped under `com.callpod.*` and `com.keepersecurity.*`) and more terminals (Ghostty, kitty, Alacritty, WezTerm, Hyper). A bundle-id list always lags reality, so there is now a second, id-independent guard: new `SecretFieldHeuristic` in `LexiconBarKit` refuses a field whose accessibility identifier, placeholder, title, help, description or role description, or the title of its window, contains any of `password`, `passphrase`, `secret`, `token`, `api key`, `private key`, `seed`, `mnemonic`, `recovery`, `pin`, `cvv`, `security code`, `otp`, `totp`, `2fa`, `credential`, `keychain`, `vault`, `card number`, `social security` and friends, in any app. Matching is on whole words after splitting camel case, snake case and punctuation, so `apiKeyField`, `api_key` and "Recovery phrase" match while "shipping" never matches "pin", "tokenizer" never matches "token" and an ordinary Notes field is left alone. Both refusals now happen when focus lands rather than when a burst is ready, so a field in a vault is never watched and no snapshot of it is ever held: the log says `not watching com.apple.Terminal: excluded` or `not watching this field in <app>: it looks like it holds a secret (recovery)`. Verified live: an ordinary, unmasked `<textarea aria-label="Recovery phrase">` in Safari is refused while an unlabelled one beside it is still corrected. docs/MACOS-APP.md now lists exactly what is excluded and how to add your own app's bundle id.

### Security
- CLI output is sanitized against terminal escape injection: paths, canonicals, aliases, notes, harvest evidence and quoted error text pass through the new `sanitizeForDisplay`; `renderTable` sanitizes every cell. `normalize` stdout is unchanged.

- Project `.lexicon.yaml` files are skipped until approved with `lexicon trust` (preview, sha256 pinned in `<config dir>/trust.json`; `lexicon trust --list`, `lexicon untrust`). A changed file drops back to untrusted until re-trusted. `LEXICON_TRUST_ALL=1` bypasses the gate for CI. `loadLexicon()` takes `includeUntrusted` and reports `projectTrust` / `skippedProject`; `list`, `normalize` (`--include-untrusted`) and `doctor` warn; the hooks and `lexicon://me` add a one-line note naming the path, never the contents.
- Project-scope writes (`init --project`, `add --project`, `import --project`, `learn --project`, `harvest --add`, `review --project`, and the MCP `add_term`, `learn_correction` and `harvest_repo {add: true}` tools) pin the file they wrote as trusted only when it did not exist yet or was already trusted. An existing untrusted or changed file makes the write fail with `ProjectTrustError` before anything is read, so a hostile repo file can never be laundered into trust. `recordHits` silently skips untrusted project files.
- Schema hardening: canonical/alias at most 80 characters, notes/phonetic 200, 64 aliases per term, 5000 terms, no control characters or line breaks; zero-width, bidi and BOM characters are stripped. Lexicon files over 2 MB and imports over 8 MB are refused. The `claude-md` export escapes `|` and line breaks in table cells. See SECURITY.md.

### Internal

- ESM, NodeNext, no default exports, no `any` in public signatures. Cross-module imports go through `src/core/index.js` only.
- `harvest.ts` exports `HARVEST_STOPLIST` (README-word filter), distinct from `matcher.ts` `STOPLIST` (prose guard), to avoid an `export *` collision.
- `src/mcp/server.ts` keeps an `EXPORT_FORMAT_VALUES` tuple with a compile-time exhaustiveness check against `ExportFormat`.
- `hookConfigFor` and `mergeHookIntoSettings` take an optional list of events; `HOOK_EVENTS` is `['UserPromptSubmit', 'SessionStart']`.
- The hook, CLI and daemon tests inject IO and clipboard functions; MCP and CLI tests mock `src/core/index.js`.
- `src/hooks/user-prompt-submit.ts` exports `dropCorrectionSpans(result, correction)` (pure; returns the same object when nothing overlaps). `parseCorrection` runs before `normalize` in the hook so the filter can apply.
- `docs/DOGFOOD.md` records the live run against Claude Code 2.1.257 that found both hook bugs.
