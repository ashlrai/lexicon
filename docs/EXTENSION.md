# Browser extension: Lexicon for voice chats

Fixes the brand, product and people names speech-to-text gets wrong inside the message box of ChatGPT, Claude, Grok, Gemini, Perplexity, Poe and Copilot, before the message is sent. Manifest V3; Chrome, Edge and Brave from `extension/dist`, Firefox from `extension/dist-firefox`.

```text
You dictate:   "tell ashler to deploy on head sner"
The box shows: "tell ashler to deploy on head sner"
You press Enter. The extension rewrites the box to
               "tell Ashlr.AI to deploy on Hetzner"
shows a toast listing both fixes (with Undo), then sends.
```

## Build

```bash
npm run build:extension
```

Produces `extension/dist` (Chromium), `extension/dist-firefox` (same files, Firefox manifest) and, when `zip` is on the PATH, `extension/lexicon-extension.zip` and `extension/lexicon-extension-firefox.zip`. CI builds it on every push and uploads `extension/dist` as the `lexicon-extension` artifact, so you can download it from the Actions run without a checkout.

What is in `dist`:

| file | source | notes |
|---|---|---|
| `core.js` | `extension/src/core.ts` | the browser-safe slice of `src/core` (schema, matcher, normalize, suggest) plus `yaml`; one ESM chunk shared by the worker and the options page |
| `background.js` | `extension/src/background.ts` | module service worker; holds the token, does every fetch |
| `content.js` | `extension/src/content.ts` | classic script injected into the chat sites; never sees the token |
| `popup.js`, `popup.html` | `extension/src/popup.ts` | toolbar popup |
| `options.js`, `options.html` | `extension/src/options.ts` | options page |
| `ui.css` | `extension/static/ui.css` | popup + options styling |
| `icons/icon-{16,48,128}.png` | generated by the build script | no binary assets in the repo |
| `manifest.json` | `extension/manifest.json` | `version` injected from `package.json` |

The build fails if a `node:` builtin reaches any bundle, or if a bundle other than `core.js` grows past 200 KB (which means it inlined the core instead of importing `./core.js`).

## Install (unpacked)

Chrome, Edge, Brave:

1. Open `chrome://extensions` (`edge://extensions`, `brave://extensions`).
2. Turn on **Developer mode** (top right).
3. **Load unpacked** and pick `extension/dist`.
4. Pin the "Lexicon" toolbar icon if you want the popup handy.

Firefox (temporary add-on; it is unloaded when Firefox quits):

1. Open `about:debugging#/runtime/this-firefox`.
2. **Load Temporary Add-on...** and pick `extension/dist-firefox/manifest.json`.

## Pair with the local API

The extension prefers the local server because that uses the same lexicon files, trust gate and hit counters as the CLI, the MCP server and the hook.

```bash
lexicon serve            # starts http://127.0.0.1:41733
lexicon serve --show     # prints the bearer token
```

Open the extension's **Options** (popup, top right, or the extension's details page), paste the token, click **Test connection**. The popup then reads "Local API" with the server version and term count.

Endpoints used, all on `127.0.0.1:41733`: `GET /health` (no auth), `POST /normalize`, `POST /learn`, `GET /lexicon` (bearer token). CORS on the server is granted only to `chrome-extension://` and `moz-extension://` origins; a web page cannot call it.

## Modes

| mode | where corrections run | when to use |
|---|---|---|
| **Local API** (default) | `lexicon serve` on this machine | you already use the CLI or the Claude Code plugin; one lexicon everywhere |
| **Embedded lexicon** | inside the extension, from the YAML in Options | no server, another machine, or you want the extension fully self-contained |

With **Local API** selected, the extension falls back to the embedded lexicon whenever `/health` fails (server stopped, token rejected, timeout). The popup shows "Embedded (fallback)" and why. Nothing is queued or dropped: every send is corrected by whichever engine is available.

**Sync from local API** (Options) pulls `GET /lexicon` into the embedded YAML, so the fallback carries your real terms rather than the example file. The YAML editor validates with the same `parseLexicon` the CLI uses and refuses to save an invalid file.

**Live** (off by default) also corrects while you type: after 400 ms of idle it normalizes the text before the caret and rewrites only that part. Leave it off if your dictation tool streams partial words into the box.

## What triggers a correction

- **Enter** (without Shift) in the composer, or a **click on the send button**. Both are intercepted in the capture phase, the text goes to the background worker, corrections are written back, a toast lists them for 3 seconds with **Undo**, then the original Enter or click is re-dispatched.
- Text the worker already vetted as unchanged (checked on a short debounce while you type) is not intercepted at all: zero added delay for ordinary sentences.
- Rich editors (ProseMirror on ChatGPT and Claude, Lexical on Perplexity, Quill on Gemini) get ranged `insertText` edits, the same path an IME or spellcheck uses, so their internal state stays in sync and formatting survives. Textareas get the React-safe native setter plus an `input` event.
- Code spans, fenced blocks, URLs and emails are never touched (`skipCode` in the core matcher).
- **Undo** puts the original wording back in the box. If the message already went out it cannot unsend it; it gives you the dictated text to resend.

## Supported sites

| site | composer selector | send button | verified |
|---|---|---|---|
| ChatGPT (`chatgpt.com`, `chat.openai.com`) | `#prompt-textarea` (ProseMirror), `textarea#mobile-composer-prompt` | `button[data-testid="send-button"]`, `button[aria-label="Send prompt"]`, `button[aria-label="Send message"]` | logged-out composer live; logged-in `#prompt-textarea` assumed |
| Claude (`claude.ai`) | `div[contenteditable="true"].ProseMirror` | `button[aria-label="Send message"]` | assumed (login wall) |
| Grok (`grok.com`) | `form textarea` | `button[data-testid="chat-submit"]` | live |
| Grok on X (`x.com/i/grok`) | focused editable | re-dispatched Enter | assumed |
| Gemini (`gemini.google.com`) | `div.ql-editor[contenteditable="true"]` (Quill) | `button.send-button` | live |
| Perplexity (`www.perplexity.ai`) | `#ask-input[contenteditable="true"]` (Lexical) | `button[aria-label="Submit"]` | live |
| Poe (`poe.com`) | `textarea[class*="GrowingTextArea"]` | `button[class*="SendButton"]` | assumed (login wall) |
| Copilot (`copilot.microsoft.com`) | `textarea#userInput` | `button[data-testid="submit-button"]` | assumed (login wall) |
| any other site (opt-in) | the focused `textarea` / `[contenteditable]` | re-dispatched Enter | n/a |

"Verified" means the selector was read from the live DOM in September 2026. These apps change their markup without notice; the table lives in `extension/src/adapters.ts` and every entry has a broad fallback. When a site stops working, fix that one row.

Each site has an on/off switch in the popup (for the current tab) and in Options (all of them). **Any site** in Options asks for the optional `<all_urls>` permission and registers the content script everywhere else, using the focused text box as the composer.

## Popup

- Engine and server status ("Local API, lexicon 0.1.0, 42 terms" or "Embedded (fallback), server: connection refused").
- On/off for this site.
- The last five corrections.
- **Learn a word**: "It's `Ashlr.AI` not `Ashler`". Posts to `/learn` when the API is up, otherwise adds the alias to the embedded YAML (comments in the YAML are preserved).

## Limitations

- **Voice modes are out of reach.** ChatGPT Voice, Claude voice mode and Gemini Live send audio straight to the server; no text passes through the composer, so there is nothing to rewrite. The extension covers dictation that lands in the text box: Wispr Flow, Superwhisper, macOS/Windows dictation, the browser's own mic button on Grok and others, or the "dictate" mic on ChatGPT that fills the composer before sending.
- The extension cannot fix a transcript the site produced server-side after you sent audio. For those, give the model the vocabulary instead: `lexicon export claude-md` into custom instructions or memory.
- Sites re-render the composer often. The guard listens at the document level and re-finds the composer per event, but a redesign can still move the send button; then Enter still works (it is re-dispatched to the composer) and only the button path needs a new selector.
- Corrections run on the whole box at send time. Very long messages (many thousands of characters) add a few milliseconds through the API and a few more embedded.
- The synthetic Enter is not "trusted" (`isTrusted: false`). Every supported site handles it today; a site that filters on `isTrusted` would need the send-button path, which is why each adapter carries both.

## Privacy

- The only network destination is `http://127.0.0.1:41733`, declared as a host permission. There is no telemetry, no update check and no third-party request. The embedded mode makes no request at all.
- The API token lives in `chrome.storage.local` and is used by the background worker only. Content scripts message the worker and receive results; the token is never exposed to page context.
- Text is sent to the local server only when you send a message (or on the live/precheck debounce while typing in a supported composer). Nothing is stored except the last five corrections shown in the popup and your settings.
- Host permissions are limited to the listed chat sites plus loopback. "Any site" is opt-in and asks for `<all_urls>` at the moment you switch it on.

## Firefox notes

- `extension/dist-firefox` swaps `background.service_worker` for `background.scripts` (with `type: module`) and adds `browser_specific_settings.gecko.id`, which Firefox needs for MV3 add-ons. Everything else is identical.
- Firefox loads it as a temporary add-on only (no signing). It is removed when Firefox exits; reload it from `about:debugging`.
- Firefox MV3 does not grant host permissions at install time. After loading, open the extension's permissions panel (`about:addons` > Lexicon > Permissions) and allow the chat sites, or accept the prompt the first time you open one.
- `chrome.*` calls are used throughout; Firefox exposes the same namespace with promise support for MV3.

## Development

```bash
npm run build:extension                          # rebuild dist/
npx tsc -p extension/tsconfig.json --noEmit      # typecheck the extension sources (DOM + chrome types)
npx vitest run tests/extension.test.ts           # jsdom tests: adapters, rewrite, Enter/click, toast, embedded, routing
```

The content script logic lives in `extension/src/content-core.ts` and takes its DOM and messaging channel as parameters; `content.ts` is the thin `chrome.*` wiring. Same split for `background-core.ts` / `background.ts`. Tests drive the cores under jsdom with a fake background and a mocked `chrome.runtime`.

### Manual checklist

The tests cover the DOM logic; a real browser is still needed for the editor integrations. After `npm run build:extension` and Load unpacked:

1. `lexicon serve` running, token pasted, **Test connection** shows the version. Popup reads "Local API".
2. ChatGPT: type `ping ashler`, press Enter. The box changes to `ping Ashlr.AI`, the toast lists the fix, the message is sent with the corrected text. Repeat with the send button. Repeat with Shift+Enter (newline, no correction).
3. Claude.ai: same as 2. Check a two-paragraph message keeps both paragraphs.
4. Gemini and Perplexity: same as 2 (Quill and Lexical editors).
5. Grok: textarea; same as 2.
6. Stop the server. Popup reads "Embedded (fallback)". `ping ashler` still becomes `ping Ashlr.AI` (example lexicon or the synced one).
7. Options > Embedded lexicon: break the YAML, confirm Save refuses; fix it, **Sync from local API** with the server up, confirm the term count.
8. Popup > Learn: "It's `Entire.io` not `entire dot io`", then dictate `open entire dot io`.
9. Popup > switch the site off; Enter sends the raw text with no toast.
10. Options > Any site, accept the permission, open a plain `<textarea>` page (any form), confirm corrections run on Enter.
11. Live mode on: type `ping ashler and`, pause; the first word is fixed while you keep typing.
