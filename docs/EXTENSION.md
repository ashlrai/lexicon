# Browser extension: Lexicon for voice chats

Fixes the brand, product and people names speech-to-text gets wrong inside the message box of ChatGPT, Claude, Grok, Gemini, Perplexity, Poe and Copilot, before the message is sent. Manifest V3; Chrome, Edge and Brave from `extension/dist`, Firefox from `extension/dist-firefox`.

```text
You dictate:   "tell ashler to deploy on head sner"
The box shows: "tell ashler to deploy on head sner"
You press Enter. The extension rewrites the box to
               "tell Ashlr.AI to deploy on Hetzner"
shows a toast listing both fixes (with Undo), then sends.
```

## Get it

Every release attaches both builds. Download the one for your browser from the
[latest release](https://github.com/ashlrai/lexicon/releases/latest):

| Browser | Asset | Unzip to |
|---|---|---|
| Chrome, Edge, Brave | `lexicon-extension.zip` | any folder you will keep |
| Firefox | `lexicon-extension-firefox.zip` | any folder you will keep |

Unzip it somewhere permanent, because Chrome loads an unpacked extension from
that path on every start and will drop it if the folder moves. Then follow
[Install (unpacked)](#install-unpacked), picking the unzipped folder in place of
`extension/dist`.

There is no Chrome Web Store or AMO listing yet, so unpacked is the only route
for now. Building it yourself is the alternative, and the one to take if you are
changing the extension.

## Build

```bash
npm run build:extension
```

Produces `extension/dist` (Chromium), `extension/dist-firefox` (same files, Firefox manifest) and, when `zip` is on the PATH, `extension/lexicon-extension.zip` and `extension/lexicon-extension-firefox.zip`, which are the two assets the release attaches. CI also builds it on every push and uploads `extension/dist` as the `lexicon-extension` artifact, so a reviewer can pull an unreleased build straight from the Actions run.

What is in `dist`:

| file | source | notes |
|---|---|---|
| `core.js` | `extension/src/core.ts` | the browser-safe slice of `src/core` (schema, matcher, normalize, suggest) plus `yaml`; one ESM chunk shared by the worker and the options page |
| `background.js` | `extension/src/background.ts` | module service worker; holds the token, does every fetch |
| `content.js` | `extension/src/content.ts` | classic script injected into the chat sites; never sees the token |
| `pair.js` | `extension/src/pair.ts` | classic script that runs only on `http://127.0.0.1:41733/pair` (and `localhost`), or on another port's `/pair` once Options was granted that port; reads the token the server put in the page and hands it to the worker |
| `popup.js`, `popup.html` | `extension/src/popup.ts` | toolbar popup |
| `options.js`, `options.html` | `extension/src/options.ts` | options page |
| `ui.css` | `extension/static/ui.css` | popup + options styling |
| `icons/icon-{16,48,128}.png` | generated by the build script | no binary assets in the repo |
| `manifest.json` | `extension/manifest.json` | `version` injected from `package.json` |

The build fails if a `node:` builtin reaches any bundle, or if a bundle other than `core.js` grows past 200 KB (which means it inlined the core instead of importing `./core.js`).

## Install (unpacked)

Below, "the extension folder" means whatever you unzipped from the release, or
`extension/dist` (`extension/dist-firefox` for Firefox) in a checkout you built.

Chrome, Edge, Brave:

1. Open `chrome://extensions` (`edge://extensions`, `brave://extensions`).
2. Turn on **Developer mode** (top right).
3. **Load unpacked** and pick the extension folder.
4. Pin the "Lexicon" toolbar icon if you want the popup handy.

Firefox (temporary add-on; it is unloaded when Firefox quits):

1. Open `about:debugging#/runtime/this-firefox`.
2. **Load Temporary Add-on...** and pick `manifest.json` inside the extension folder.

## Pair with the local API

The extension prefers the local server because that uses the same lexicon files, trust gate and hit counters as the CLI, the MCP server and the hook. Pairing is one command:

```bash
lexicon serve --install  # once: start the server at login (or run `lexicon serve` in a terminal)
lexicon serve --pair     # opens http://127.0.0.1:41733/pair in your default browser
```

`--pair` checks that serve is configured (it never creates `serve.json`; run `lexicon serve --install` or `lexicon serve` first) and that the server answers `/health`, then opens the pairing page with `open` (macOS), `xdg-open` (Linux) or `start` (Windows). The page says "Pairing Lexicon..." and carries the bearer token in a `<meta name="lexicon-token">` tag. The extension's `pair.js` content script, which runs only on that page, reads the token and asks the background worker to pair; the worker proves the token against `GET /stats` (a bearer route; `/health` needs no token so it proves nothing), stores the base URL and token, switches the mode to **Local API**, and the page changes to "Paired with lexicon serve (N terms)". If no extension answers within 3 seconds the page shows install instructions instead. Open the popup afterwards: it reads "Local API" with the server version and term count.

If the browser that opened is not the one with the extension, copy the URL into the right one, or click **pair in this browser** on the extension's Options page, which links to the same `/pair` URL. Options shows "Paired with http://127.0.0.1:41733 (token stored)" once a token is in place, and **pair again** if the token was rotated (delete `serve.json` and restart the server to rotate it).

### A server on another port

The manifest grants the extension port 41733 only, and `pair.js` runs on that port's `/pair` page only, so `lexicon serve --port 5000 --pair` opens a page nothing answers (it then says how to pair, and so does `--pair` itself). Pair it from Options instead: set **Base URL** to `http://127.0.0.1:5000` and click **pair in this browser**. The browser asks once for access to `http://127.0.0.1:5000` and `http://localhost:5000` (taken from the optional permission, so the manifest asks for nothing more up front); the extension then runs `pair.js` on that port's `/pair` page and opens it, and pairing goes on as above. Refuse the prompt and Options says how to retry; the `lexicon serve --show` token pasted below still works. Each port you pair this way keeps its own script, so pairing a third port does not undo the second. Removing a port's access in the browser stops the script on that port only.

Manual fallback, for a browser profile the CLI cannot open: `lexicon serve --show` prints the token; paste it into **Options > Local API > Token** and click **Test connection**.

The pairing page is served without a token but only to a loopback client whose `Host` header names this server, and it exposes nothing a local process could not already read from `serve.json`. That boundary, the routes the extension uses, and the CORS rule that lets an extension origin call the API while a web page cannot, are all in [LOCAL-API.md](LOCAL-API.md).

## Modes

| mode | where corrections run | when to use |
|---|---|---|
| **Local API** (default) | `lexicon serve` on this machine | you already use the CLI or the Claude Code plugin; one lexicon everywhere |
| **Embedded lexicon** | inside the extension, from the YAML in Options | no server, another machine, or you want the extension fully self-contained |

With **Local API** selected, the extension falls back to the embedded lexicon when `/health` fails (server stopped, `/health` timed out or reported not ok) and when the server answers `/health` but the correction itself cannot go through: no token stored, the token rejected (`/normalize` answers 401; `/health` needs no token, so it never sees a bad one) or holding a character a token never has (a smart quote or non-breaking space from a paste, which is never sent and is reported as a token problem, not as a server that cannot be reached), or `/normalize` failing or timing out. The popup shows "Embedded (fallback)" and why: it checks the stored token against `GET /stats`, so a missing or rejected token shows there too, not only on the next send. A toast for a send the embedded lexicon corrected in that state reads "embedded (fallback)" and ends with `Local API not used:` and the same reason, commands shown as code. Nothing is queued or dropped: every send is corrected by whichever engine is available.

**Sync from local API** (Options) pulls `GET /lexicon` into the embedded YAML, so the fallback carries your real terms rather than the example file. It reports `Synced N terms from the local API.`, and when the server left a repo `.lexicon.yaml` out because it is untrusted or changed since it was trusted, it names that file and says to review it and run `lexicon trust` in that repo, then sync again: its terms are not in the synced YAML. The YAML editor validates with the same `parseLexicon` the CLI uses and refuses to save an invalid file.

**Live** (off by default) also corrects while you type: after 400 ms of idle it normalizes the text before the caret and rewrites only that part, then puts the caret back where you were typing. Leave it off if your dictation tool streams partial words into the box.

## What triggers a correction

- **Enter** (without Shift) in the composer, or a **click on the send button**. Both are intercepted in the capture phase, the text goes to the background worker, corrections are written back, a toast lists them for 3 seconds with **Undo**, then the original Enter or click is re-dispatched. A browser runs no default action for a re-dispatched Enter, so when no page handler takes it and the site has no known send button (any site other than the listed chat apps), the extension finishes the press itself: a newline in a textarea or rich text box, or the form's submit for a one-line field (its default button, or, without one, the form itself only when that field is its only text field, as a browser does).
- Text the worker already vetted as unchanged (checked on a short debounce while you type) is not intercepted at all: zero added delay for ordinary sentences.
- Rich editors (ProseMirror on ChatGPT and Claude, Lexical on Perplexity, Quill on Gemini) get ranged `insertText` edits, the same path an IME or spellcheck uses, so their internal state stays in sync and formatting survives. Textareas get the React-safe native setter plus an `input` event.
- Code spans, fenced blocks, URLs and emails are never touched (`skipCode` in the core matcher).
- **Undo** puts the original wording back in the box. If the message already went out it cannot unsend it; it gives you the dictated text to resend, but only into an empty box: once you have edited the text or started the next message, Undo leaves the box alone. In live mode Undo also restores the text after the caret, and the restored wording is not corrected straight back, by live mode or by the next Enter; type more and live mode checks the new text again.

## Supported sites

| site | composer selector | send button | verified |
|---|---|---|---|
| ChatGPT (`chatgpt.com`, `chat.openai.com`) | `textarea#mobile-composer-prompt` (logged out), `#prompt-textarea` (ProseMirror, logged in) | `button[aria-label="Send message"]` (logged out), `button[data-testid="send-button"]`, `button[aria-label="Send prompt"]` | logged-out composer verified 2026-09-19; logged-in `#prompt-textarea` assumed |
| Claude (`claude.ai`) | `div[contenteditable="true"].ProseMirror` | `button[aria-label="Send message"]` | assumed (login wall on 2026-09-19) |
| Grok (`grok.com`) | `form div.tiptap[contenteditable="true"]` (Tiptap/ProseMirror), fallbacks `form textarea`, `textarea[placeholder*="Grok" i]` | `button[data-testid="chat-submit"]` | verified 2026-09-19 (composer moved from a textarea to Tiptap; adapter updated) |
| Grok on X (`x.com/i/grok`) | focused editable | re-dispatched Enter | assumed |
| Gemini (`gemini.google.com`) | `rich-textarea div.ql-editor[contenteditable="true"]` (Quill) | `button[aria-label="Send message"]` (`button.send-button` no longer present) | verified 2026-09-19 (logged-out `/app`) |
| Perplexity (`www.perplexity.ai`) | `#ask-input[contenteditable="true"]` (Lexical) | `button[aria-label="Submit"]` | verified 2026-09-19 (two-correction rewrite needed the per-edit settle in `editable.ts`) |
| Poe (`poe.com`) | `textarea[class*="GrowingTextArea"]` | `button[class*="SendButton"]` | assumed (login wall on 2026-09-19) |
| Copilot (`copilot.microsoft.com`) | `textarea#userInput` | `button[data-testid="submit-button"]` | assumed (login wall on 2026-09-19) |
| any other site (opt-in) | the focused `textarea` / `[contenteditable]` | re-dispatched Enter | verified 2026-09-19 on a plain `<form><textarea>` page |

"Verified" means the built `content.js` was injected into the live page on that date with a fake `chrome.runtime` bridge (replies recorded from the real local API), `ping ashler about cooper netties` was typed, Enter was dispatched, and the composer read `ping Ashlr.AI about Kubernetes` with the toast shown; the re-dispatched Enter was swallowed by the harness so nothing was sent. "Assumed" rows sit behind a login wall and are taken from public DOM reports. These apps change their markup without notice; the table lives in `extension/src/adapters.ts` and every entry has a broad fallback. When a site stops working, fix that one row.

Each site has an on/off switch in the popup (for the current tab) and in Options (all of them, including each site the extension has checked text on through **Any site**). **Any site** in Options asks for the optional `<all_urls>` permission and registers the content script everywhere else (in frames too, and, in Chrome 119 and later, in an `about:blank` or `blob:` editor frame, matched by the page that made it), using the focused text box as the composer. A one-line field that holds an identifier is never a composer: one whose `autocomplete` names a username, email, one-time code, password, phone, URL or card field, and any text field in a form with a password field, so a login form's username is never rewritten. Code is never a composer either: the editable of a code editor (CodeMirror, Monaco, Ace), a contenteditable `<pre>` or `<code>`, and, on any site, a rich text box that embeds a code editor or has the caret in a code block or inline code, so Enter in an editor never rewrites code. On every site a code block or inline code typed into the composer is left as typed while the prose around it is corrected: the code goes to the engine blanked out, so it is never matched or counted.

A composer inside an iframe is covered when the frame is part of the page (same origin, including an `about:blank` editor frame, judged by the page's own settings) or is itself one of the chat sites embedded in another page; a frame from any other origin (an ad, a payment field, a third-party widget) is left alone. A frame follows the site switch of the tab it is in.

## Popup

- Engine and server status ("Local API, lexicon 0.5.2, 42 terms" or "Embedded (fallback), server: cannot reach lexicon serve at http://127.0.0.1:41733; start it with `lexicon serve`"). The same sentence is what **Test connection** and **Sync from local API** in Options say when the server is not running. Each reason the local API is not in use ends with its fix: with no token stored it adds `no token set: once the server is running, run lexicon serve --pair` (or, with the server up, `server up (lexicon X), but no token set: run lexicon serve --pair`), a rejected token names `lexicon serve --show` and `lexicon serve --pair`, and a broken embedded YAML says `fix it under Options > Embedded lexicon`. **Test connection** says `Connected` only when the server is up and a token is stored; with the server up and no token it says `Server is up, not paired` and names `lexicon serve --pair`.
- On/off for this site.
- The last five corrections.
- **Learn a word**: "It's `Ashlr.AI` not `Ashler`". Posts to `/learn` when the API is up and accepts the stored token, otherwise adds the alias to the embedded YAML (comments in the YAML are preserved): the same rule that decides where a send is corrected. When the server is up but no token is stored or it rejects the token, the message says the word went to the embedded lexicon only, why, and that **Sync from local API** replaces the embedded YAML, so learn it again once paired. With **Local API** selected and the server not running, it says the same with the `lexicon serve` command and "learn it again once the server is running". A `/learn` the server refuses for another reason (bad input, an untrusted project lexicon) shows the server's error and writes nothing. When the server reports that another term also holds the spelling, the message says so and names the `lexicon remove ... --alias ... --global` (or `--project`) command that drops it; an untrusted project lexicon that claims it too is named by path.

## Limitations

- **Voice modes are out of reach.** ChatGPT Voice, Claude voice mode and Gemini Live send audio straight to the server; no text passes through the composer, so there is nothing to rewrite. The extension covers dictation that lands in the text box: Wispr Flow, Superwhisper, macOS/Windows dictation, the browser's own mic button on Grok and others, or the "dictate" mic on ChatGPT that fills the composer before sending.
- The extension cannot fix a transcript the site produced server-side after you sent audio. For those, give the model the vocabulary instead: `lexicon export claude-md` into custom instructions or memory.
- Sites re-render the composer often. The guard listens at the document level and re-finds the composer per event, but a redesign can still move the send button. On a built-in site whose send button no longer matches, Enter is held for the check only once the page is seen to take a replayed or real Enter (it cancels the event); until then the press goes on as typed, uncorrected, rather than being held for a replay that might not send. If a check ends with neither the replayed Enter taken nor a button to click, the toast says the message was not sent and the next Enter goes through as typed.
- Corrections run on the whole box at send time. Very long messages (many thousands of characters) add a few milliseconds through the API and a few more embedded. Either engine stops matching after a fixed budget (1 s for the API, 250 ms embedded) and applies what it found up to that point, so a huge paste never holds the send. A composer over 1 MB of text (`MAX_COMPOSER_CHARS`, the same limit `lexicon serve` puts on a request) is not checked at all: nothing is sent while typing, and Enter or the send button goes on as typed with a toast that says it was not checked.
- The synthetic Enter is not "trusted" (`isTrusted: false`). Every supported site handles it today; a site that filters on `isTrusted` would need the send-button path, which is why each adapter carries both.

## Privacy

- The only network destination is `http://127.0.0.1:41733` (also reachable as `localhost:41733`), declared as a host permission. There is no telemetry, no update check and no third-party request. The embedded mode makes no request at all.
- The API token lives in `chrome.storage.local` and is used by the background worker only. Content scripts on the chat sites message the worker and receive results; the token is never exposed to page context. The one content script that does see the token is `pair.js`, which runs only on the server's own `/pair` page (the page that printed the token) and forwards it to the worker over runtime messaging.
- Text is sent to the local server only when you send a message (or on the live/precheck debounce while typing in a supported composer). Nothing is stored except the last five corrections shown in the popup, your settings, and the host names (no paths, no text) of the sites checked through "Any site", at most 100, so Options can list them with a switch.
- Host permissions are limited to the listed chat sites plus loopback. "Any site" is opt-in and asks for `<all_urls>` at the moment you switch it on.

## Firefox notes

- `extension/dist-firefox` swaps `background.service_worker` for `background.scripts` (with `type: module`) and adds `browser_specific_settings.gecko` (the id Firefox needs for MV3 add-ons, and `strict_min_version` 127.0). Everything else is identical.
- Firefox 127 or later is required: from 127 Firefox grants an MV3 add-on's host permissions when it is installed. Earlier releases left the chat sites and the local server unpermitted until each was allowed by hand, so the minimum was raised rather than asking for them at runtime.
- Firefox loads it as a temporary add-on only (no signing). It is removed when Firefox exits; reload it from `about:debugging`.
- The install grants the chat sites and `127.0.0.1` / `localhost` port 41733, but Firefox lets you revoke each one afterwards. If one was revoked, open the extension's permissions panel (`about:addons` > Lexicon > Permissions) and allow it again: without the loopback ones pairing from the `/pair` page, Test connection and Sync fail and corrections use the embedded lexicon.
- `chrome.*` calls are used throughout; Firefox exposes the same namespace with promise support for MV3.

## Development

```bash
npm run build:extension                          # rebuild dist/
npx tsc -p extension/tsconfig.json --noEmit      # typecheck the extension sources (DOM + chrome types); npm run typecheck runs it too
npx vitest run tests/extension.test.ts           # jsdom tests: adapters, rewrite, Enter/click, toast, embedded, routing
```

The content script logic lives in `extension/src/content-core.ts` and takes its DOM and messaging channel as parameters; `content-boot.ts` decides which frames it runs in; `content.ts` is the thin `chrome.*` wiring. Same split for `background-core.ts` / `background.ts`. `pair.ts` exports `pairFromDocument({ doc, send })` and auto-runs only when `chrome.runtime.id` is set. Tests drive the cores under jsdom with a fake background and a mocked `chrome.runtime`.

### Manual checklist

The tests cover the DOM logic; a real browser is still needed for the editor integrations. After `npm run build:extension` and Load unpacked:

1. `lexicon serve` running, `lexicon serve --pair`: the tab reads "Paired with lexicon serve (N terms)". Options shows "Paired with http://127.0.0.1:41733 (token stored)"; **Test connection** shows the version. Popup reads "Local API". Also once with the token pasted by hand.
2. ChatGPT: type `ping ashler`, press Enter. The box changes to `ping Ashlr.AI`, the toast lists the fix, the message is sent with the corrected text. Repeat with the send button. Repeat with Shift+Enter (newline, no correction).
3. Claude.ai: same as 2. Check a two-paragraph message keeps both paragraphs.
4. Gemini and Perplexity: same as 2 (Quill and Lexical editors).
5. Grok: textarea; same as 2.
6. Stop the server. Popup reads "Embedded (fallback)". `ping ashler` still becomes `ping Ashlr.AI` (example lexicon or the synced one).
7. Options > Embedded lexicon: break the YAML, confirm Save refuses; fix it, **Sync from local API** with the server up, confirm the term count.
8. Popup > Learn: "It's `Entire.io` not `entire dot io`", then dictate `open entire dot io`.
9. Popup > switch the site off; Enter sends the raw text with no toast.
10. Options > Any site, accept the permission, open a plain `<textarea>` page (any form), confirm corrections run on Enter.
11. Live mode on: type `ping ashler and`, pause; the first word is fixed while you keep typing.
